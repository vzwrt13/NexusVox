# Meeting internals

The recorder, the stored transcript job, the live preview and the session. For users: `docs/MEETINGS.md`. Module paths such as `app/core.py` are relative to `src/nexusvox/`; paths that start with a top-level folder (`tests/`, `docs/`, `docker/`, `scripts/`) are from the repository root.

## Meeting Recorder

`meetings/recorder.py` - records the default microphone and the system output (WASAPI loopback) at the same time into one folder per meeting (`<base>/meeting-YYYYMMDD-HHMMSS/`: `mic.wav`, `system.wav`, `meeting.json`). Independent of dictation: own streams, nothing in `audio/capture.py` changed, so dictation keeps working during a meeting (`app/cycle.py` only reports each take's time range). Started from the dashboard and the meeting hotkey through `MeetingSession` (see Meeting Session below); `python -m nexusvox.meetings.recorder [--dir audio/meetings] [--seconds N]` runs it by hand. Each track keeps its device's native rate and channel count (mic via sounddevice `RawInputStream` int16; system via **PyAudioWPatch**, chosen because it ships WASAPI loopback in one wheel for Windows and sounddevice's PortAudio has none; `soundcard` was the alternative). `AudioSource` (`describe()`, `start(sink)`, `stop()`) is the seam tests fake. The audio callback only stamps the block with the clock and `put_nowait`s it onto a bounded queue (full queue: block dropped and counted in `meeting.json`); one writer thread per track streams it to a `wave` file, so memory stays flat. All tracks share one `t0`. `TrackWriter.write` knows when a block arrived and keeps the track within `GAP_TOLERANCE_S` (0.25 s) of the shared clock: the first block pads the whole offset from `t0`, a larger deficit later (loopback sends nothing during silence) is filled with zeros, a larger surplus (fast device clock) is dropped from the block, and `finish()` pads to the stop time, so both files end up as long as the meeting within that tolerance. Blocks dropped on a full queue are counted in frames and padded back before the next block. `describe()` resolves and pins the device (the loopback source keeps one PyAudio instance from `describe()` to `stop()`), all sources are described before `t0` is taken, and `start()` opens exactly that device and format. `meeting.json` (`started_at` UTC, `dictations`: `[{start_s, end_s}]` seconds from `t0` of every dictation take, `MeetingRecorder.begin_dictation` / `end_dictation` (under a lock shared with `stop()`, so a late take never rewrites the finished file), rewritten into the file at once; `App` reports each non-remote take through an executor (`_begin_take` after the recording started, from the hotkey press (`_press_time`) so a slow server connection does not cut off the first words; `_end_take` at the stop and again in the cycle's `finally`, so a failed take is stored too) via `DashboardAPI.begin_dictation` / `end_dictation` -> `MeetingSession`, whatever `[meeting].leave_dictation_out` says; a take still open when the meeting stops lasts until the stop, and one that began before the meeting is cut at its start; `ended_at`, per track file/rate/channels/frames/duration, `latency_s` (the input latency the open stream reports: `MicSource.latency` = sounddevice `stream.latency`, `LoopbackSource.latency` = PyAudio `get_input_latency()`; an optional `AudioSource` method, read by `_Track.read_latency` right after the sources start, so a source without it or a failing read leaves it out), `dropped_blocks`, `error`) is written at start (`ended_at` null), again once the sources run (with `latency_s`; outside the start's abort path and under the dictation lock, so a failed write is only logged and never stops a running recording) and again at stop; `stop()` closes every track even when one fails and records the failure in `meeting.json`; a failed `start()` removes the folder and raises the original error. A process killed mid-meeting leaves WAV headers with a wrong length; `meetings/transcribe.py` `load_meeting` repairs them (see Meeting Transcript below). Tests: `tests/test_meeting_recorder.py` (fake sources and clock, including 60 simulated minutes with flat memory).

## Meeting Transcript

`meetings/transcribe.py` + `DashboardAPI.transcribe_meeting` / `start_meeting_transcription(folder)` (runs on the same `FileJobs` as uploads; `DashboardAPI.stop_meeting` starts it when a recording ends; the save, extension hook and result dict are shared with uploads in `_store_file_transcription`). `load_meeting` reads `meeting.json` and repairs each WAV header from the actual file size (`repair_wav_header`: only opened for writing when the header is wrong, RIFF and data sizes rewritten, a partial last frame cut). `ended_at: null` marks the folder interrupted (a note), its tracks are still transcribed - but the recorder also writes null while recording, and its WAV writer keeps the headers consistent, so only the age tells: a track of such a folder written to within `STALE_AFTER_S` (30 s) makes `load_meeting` raise `StillRecordingError` (`refuse_if_recent`, shared with `repair_wav_header`, which never touches a file that young). The mtime is only a hint (NTFS may not update it while a writer holds the file open, and the loopback track is idle in silence), so `DashboardAPI.transcribe_meeting` also refuses the folder `MeetingSession.is_recording` reports ("may still be recording"). Each track is read window by window (60 s of its own device rate), downmixed and resampled to 16 kHz mono (`convert_track` also writes it to a temporary 16 kHz WAV for the mix), so clock differences between the devices cannot shift one track against the other; memory holds one window plus the WAV chunks of the track being transcribed (`transcribe_file` takes a list), about 115 MB per hour, one track at a time. The chunks go through `transcribe_file(word_timestamps=True)` like an upload (no 25 MB limit on this path); the row's confidence is the mean of the tracks'. `merge_words` drops echo from the microphone words (`drop_echo`: a microphone word has an echo partner when a system-track word within `ECHO_SLACK_S` is at least `ECHO_SIMILARITY` similar (casefolded, so umlauts and ß work), and only runs of `ECHO_MIN_RUN` (3) consecutive partnered microphone words are dropped, so a lone "yes"/"okay" or "the"/"they" in crosstalk stays; bisect search, not quadratic), then (with `[meeting].leave_dictation_out`, default on, read at transcription time so a folder transcribed again (only possible while its tracks exist: after a failed job) follows the current setting) drops the microphone words that overlap a dictation range of `meeting.json` padded by `DICTATION_MARGIN_S` (0.5 s; `drop_dictation`, before the echo filter; without word timing nothing can be dropped and a note says so; the audio files are not changed), then numbers the speakers like an upload does: `speaker` 1 = the microphone (`mic.wav`), the system track's own speakers 2, 3, ... (`SPEAKER_FIRST_SYSTEM`; `transcribe_meeting` runs the system track with `diarize=True`, so speaker detection gives its words 1..N and `merge_words` moves them up by one; without detection, or when it fails, every system word is speaker 2 and the note's "the transcript has no speaker labels" ending (`NO_SPEAKER_LABELS`) becomes "everyone on it is shown as Speaker 2"), and joins the two tracks with `interleave`: time order, except that the track whose word came last keeps the turn while it is still speaking (its last word ended no more than `TURN_SLACK_S` (0.5 s) before the other track's next word, so a long pause ends the turn) and its next word starts within the slack after that one - Parakeet times the first word after a pause up to ~0.4 s early and lets the last word before one run on, which split the user's last word from their sentence at a turn change; crosstalk still alternates and no word moves more than the slack. Each track keeps the engine's own word order (no sort, even where `start` is not monotonic); `interleave` compares a running maximum of each track's starts, so a word stepping back cannot pull the other track's words into the middle of a run: one transcript is already in spoken order, also where detection switches between system speakers, so the turn rule is only needed between the tracks. Before that, `merge_words(system_offset=)` lines the tracks up by `track_offset(meeting, mic_levels, system_levels)`: the echo lag when the microphone hears the speakers (`echo_lag`: 10 ms RMS steps (`loudness_steps`, collected by `convert_track(levels=)` in the conversion pass, so no extra read) normalised and correlated over -0.05..0.5 s, a peak of at least `OFFSET_MIN_CORRELATION` 0.3 counts; turn-taking correlates below zero), else `latency_s` mic minus system (`load_meeting` keeps only finite values within 0..`MAX_LATENCY_S`; capture side only: a playback delay such as a Bluetooth headset's is not in it, only the echo path sees one), else 0. `track_shifts(offset)` turns it into a delay of one track (the microphone when negative, with the dictation ranges), never moving one earlier, so no word gets a negative time and the mix loses nothing; `mix_tracks(offsets=)` delays the same track in `meeting.wav` (`_shifted` keeps the 60 s windows aligned). A failure of the alignment is a job note and falls back to the latencies; the job logs the offset. `format_meeting(words, own_label)` is `format_transcript(words, {1: own_label})`, so the saved text has `Speaker N: ...` paragraphs with the microphone named after `[meeting].own_voice_label` (default `Speaker 1`, Settings tab, `normalize_speaker_label`). The label is also stored with the row (`file_transcriptions.speaker_names`, JSON `{"1": name}`, `FileTranscript.speaker_names`), which the built-in exports use instead of `Speaker N` (an edit of the text cannot lose it). `own_voice_label_problem` refuses `Speaker 2`..: another speaker gets that label (a hand-edited file falls back to the default). Speaker detection is skipped for a system track over `MAX_DETECTION_S` (2 h): the whole track goes to the server in one request and is held a second time as one WAV (~115 MB per hour on top of the chunks). While it runs the job progress stays at the end of the track's chunks. `TranscriptionResult.plain_text` is `text` without the `Speaker N:` labels. When a track has fewer timed words than words in its text (an engine without timing, or the server skipping words), nothing is interleaved: each track's full text follows the other, the microphone under its label and the system audio as `Speaker 2` (a note), like the upload path's `words_complete` check. `mix_tracks` writes `meeting.wav` (16 kHz mono, via a `.tmp` file moved into place, so a failed mix leaves no partial file) next to the tracks (deleted after a successful save, see below), which are never changed: each track's speech RMS (50 ms blocks within 20 dB of its loud blocks, above a noise floor) is brought to `TARGET_RMS`, with gain limited to `MIN_GAIN`..`MAX_GAIN` so a near-silent track is not boosted into noise, and the sum is scaled by `PEAK_LIMIT` / (sum of the gained track peaks) so it cannot clip; one analysis pass per track, one mixing pass. After a successful save `transcribe_meeting` deletes the track files `meeting.json` lists (also an unreadable one; a failed save leaves everything, so *Transcribe* still works; a failed mix with `store_audio` on keeps them, being the only audio) and, with `[meeting].store_audio` off (read once at the start of the job; no mix is written then, the length comes from the track frames), `meeting.wav` too (`audio_path` NULL, so the card has no player); meetings already stored are never touched. `_discard_meeting_files` writes the names to `meeting.json` under `discard` first and drops them once all are gone, and deletes only plain files directly inside the folder; `DashboardAPI.sweep_meeting_leftovers` (a thread at dashboard API start) finishes a deletion a locked file or a quit interrupted. The row is saved with `kind = "meeting"` and `audio_path` (relative to the database folder, `DashboardAPI._db_dir`); `GET /api/file-transcriptions/<id>/audio` serves it, the Upload history shows an audio player for rows that have one, and `FileTranscript.kind` carries the marker to `on_file_transcribed` (additive, `API_VERSION` stays 1).

## Meeting Live Transcript

`meetings/live.py` - `LiveTranscriber(transcribe)`: a preview of the running meeting, the microphone under `[meeting].own_voice_label` (default `Speaker 1`, read per segment via the `labels` callback, `DashboardAPI._live_labels`) and the system track as `Others` (`LIVE_OTHERS_LABEL`; no speaker detection while recording and several people may speak, so one neutral label - live only, the stored transcript after Stop keeps the numbering `Speaker 2`, `Speaker 3`, ...), never "Me"; never stored. `MeetingRecorder.set_tap(fn)` makes each `_Track.sink` also call `fn(track, AudioFormat, data)` (audio thread, exceptions swallowed and logged, so a tap can never cost a recorded block); `MeetingSession(live_factory=)` builds one `LiveTranscriber` per meeting when `[meeting].live_transcript` is on (default off - its load is not measured yet; read at start, so a change applies from the next meeting), taps the recorder before `start()`, starts the worker after it and stops it in `stop()`. `feed` only `put`s onto an unbounded `SimpleQueue` (never blocks; the worker drains it before every window, so it holds at most one transcription call's audio, and blocks are stamped with the raw clock, and `start(t0)` takes the recorder's own zero (`MeetingRecorder.t0`, taken after the devices were resolved) so live `at_s` matches mic.wav / system.wav; the recorder feeds blocks before `start()`). A worker that dies from an unexpected error sets `status().error`, stops `feed` from queueing and drops what is queued, so memory cannot grow (`feed` also drains a block that slipped in as the worker ended). A pause between blocks longer than `GAP_TOLERANCE_S` (0.25 s; a loopback sends nothing during silence) is filled with zeros in the track's pending audio like `TrackWriter` does, so `at_s` stays on the recording's timeline; a gap beyond `MAX_BACKLOG_S` drops the audio still pending (`skipped_s`); one worker thread (`_drain` before every window, which also applies the backlog limit; the track that has waited longest goes first) downmixes to mono at the device rate (`meetings/transcribe.py` `downmix` / `block_power`, shared with the stored job), collects each track until `WINDOW_S` (6 s), cuts at the quietest 50 ms block of the window's last third (max `CUT_SEARCH_S` 2 s, `_cut`), skips a window whose loudest block is under `SILENCE_RMS` (100), resamples to 16 kHz (`meetings/transcribe.py` `resample`) and calls `transcribe(pcm)` with the raw PCM16 bytes (no WAV round trip) - a `WindowTranscriber` (one transcriber from `create_transcriber` with the current model/language and one event loop for the whole meeting, both created on the first window that works: a failed `create_transcriber` is retried after a wait (`MAKE_RETRY_S` 5 s, doubling to `MAKE_RETRY_MAX_S` 60 s; windows in between fail at once with the last error, so a server that stays down costs no new transcriber per window), `LIVE_TIMEOUT_S` 20 s; a window the server did not finish raises, so it shows in `status().error`; closed by the worker when it ends). New windows wait while a dictation take runs (`LiveTranscriber.pause_while(MeetingRecorder.dictating)`). `MeetingSession.stop()` stops the worker after releasing its lock (waits up to 5 s for a window in flight; a late one is only a preview and may still finish beside the stored job). One window at a time, tracks in turn; a track further behind than `MAX_BACKLOG_S` (30 s) drops its oldest audio (`skipped_s`), a failed window is logged and lost (`status().error`). Segments `{n, speaker, label, text, at_s}`; `status()` gives `load` (share of wall time spent in the model), `windows`, `skipped_s`, `error`. No echo filter, speaker detection or dictation filter (the stored job still does all three). `MeetingSession.live(after)` keeps the finished meeting's segments until the next start. Tests: `tests/test_meeting_live.py`.

## Meeting Session

`meetings/session.py` - `MeetingSession(config.meeting, base_dir, recorder_factory)`: thread-safe `start()` / `stop()` / `status()` (`{recording, elapsed_s, folder}`) around `MeetingRecorder`, built per meeting from the current `[meeting]` devices (`MicSource(name)`, `LoopbackSource(name)`: the named device, matched on WASAPI names; a missing device logs a warning and falls back to the default; `list_devices()` feeds the dashboard selects). One session lives in `DashboardAPI` (`start_meeting`, `stop_meeting` = recorder stop + `start_meeting_transcription`, `toggle_meeting`, `shutdown_meeting` on quit so the WAV headers are closed); meetings go to `<database folder>/<[database].audio_dir>/meetings/`. A `busy` stop (another file transcribing) leaves the audio in its folder without a row. The meeting hotkey is `hotkey.MeetingHotkey`, a second pynput listener of its own (toggle, modifiers + required key, binding re-read per event, so the dashboard is live). It fires only when exactly its modifiers are held (a superset such as Ctrl+Shift+Alt+M is another shortcut) and the modifiers it counts are intersected with `GetAsyncKeyState` on every press, so a key-up the hook never saw (Ctrl+Alt+Del) cannot leave one "held"; the key is swallowed only when it fires. `meeting_hotkey_clash` / `validate_meeting_hotkey` refuse a missing key, no modifier and any chord the dictation listener also fires on (it fires on every chord that holds its modifiers and key: equal, or a superset when the dictation hotkey is modifier-only or ends in the same key); `DashboardAPI.set_hotkey` runs the same check the other way round, and `load_config` falls back through `default_meeting_hotkey` when a hand-edited file clashes. The hook only hands off to a thread (`App._toggle_meeting`, non-blocking lock: a press while the previous one is still being handled is ignored): `ensure_dashboard_api` starts the Flask server without opening the browser, `toggle_meeting(ask_consent=True)` (under `DashboardAPI._meeting_lock`, which the dashboard buttons share) answers `action` `start` / `stop` / `consent`; `consent` (hint on) opens the dashboard on `#recordings`, because the hint is shown there; a stop that only found the transcriber `busy` still plays the stop beep (the recording ended). A recording without a transcript (busy stop, quit mid-meeting, failed job) is listed by `get_pending_meetings` (folders with `meeting.json` and no `kind="meeting"` row, except the one recording or transcribing) and can be transcribed or deleted from the Recordings tab. Dictation is untouched during a meeting (separate streams and listener). `DashboardAPI.delete_file_transcription` deletes an upload (its stored audio when inside the database folder) or a meeting (the folder, found next to the mix or by name in the meetings directory, only when named `meeting-*` and holding `meeting.json`); missing files never block it. `_remove_folder` deletes `meeting.json` last, so a locked file (a player, a scanner) fails the delete with the row and the marker still there and a retry finishes it. Device lists: `_refresh_devices` re-initialises PortAudio so a headset plugged in later shows up and a saved device is found, but only while no stream is open (`audio/state.py` `streams_open()`, counted by dictation and the meeting microphone; a module of its own so reading it needs no PortAudio). A named output is matched to its loopback by the exact name `<output> [Loopback]` first, the substring only as fallback. Docs for users: `docs/MEETINGS.md`. Tests: `tests/test_meeting_dashboard.py`.
