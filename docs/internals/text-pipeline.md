# Text pipeline internals

The steps between the transcript and the typed text, in pipeline order, plus the learn-from-edits watcher. Overview: `docs/text-pipeline.html`. Rules: `src/nexusvox/CLAUDE.md`. Module paths such as `app/core.py` are relative to `src/nexusvox/`; paths that start with a top-level folder (`tests/`, `docs/`, `docker/`, `scripts/`) are from the repository root.

## Correction Dictionary

`dictation/dictionary.py` — `apply_dictionary(text, entries)` runs on the raw transcription after the nexus/assistant checks and before voice commands. Entries (`wrong` → `right`) live in the `dictionary_entries` table, edited in the dashboard Settings tab. Matching is whole-word, case-insensitive, whitespace-tolerant; longest `wrong` phrase wins; `right` is inserted verbatim. `suggest_entries(original, corrected)` diffs a review correction token-wise (case-sensitive, so "cloud code" → "Claude Code" stays one phrase) and returns only `replace` blocks — insertions/deletions are usually fillers, not misheard terms.

## Snippets (Pro)

Snippets, and the "nexus open" voice command that opened a snippet's URL, are no longer part of the core: they live in the Pro extension. The core has no snippet storage, dashboard block, API endpoint or pipeline step; `pipeline.process_text` goes dictionary -> press enter -> `protect` -> voice commands -> cleanup -> translation -> `restore` -> `on_dictation`. `snippets.py` stays only as the pure matcher that extensions import (`Snippet`, `SnippetOption`, `mark_snippets`, `expand_snippets`, `placeholders_intact`, `best_option`; its tests are `tests/test_snippets.py`) and that `polish_presets` uses to match a spoken preset name; keep its signatures stable, since Pro imports them. The `snippets` table and its `options` column are left in the database untouched (`SnippetRow` stays in `storage/models.py` so the table is still created, `tests/test_db.py` checks an old table survives); the core never reads or writes it, Pro copies the rows on first use. A voice command an extension wants to own (Pro's "nexus open <snippet>") goes through `Extension.on_command(text, ActiveApp) -> (label, opened) | None`: `App._run_command` asks `ExtensionRegistry.command` first, via `App._extension_command` in the executor and only for non-remote dictations; a `(label, opened)` answer is saved under `label`, nothing is typed, and `opened=False` plays the error cue. A malformed answer, an exception or a timeout (`HOOK_TIMEOUT_S`) is skipped and the next extension, then the core's own commands, run. Pro's snippet expansion belongs in `protect`/`restore` (`mark_snippets` in `protect`, `expand_snippets` in the returned `restore`), which also works for phone dictations.

## Voice Commands

`dictation/voice_commands.py` converts spoken phrases into characters/transforms before text injection. Runs after nexus check, only if `[voice_commands].enabled = true` in config.

- **Structural** (own category, opt-out via `structural` list, `bypass_structural` skips them all; default all on): `new line`, `new paragraph`, `tab`, `all caps`. Keywords in `structural` are the canonical English ones; their aliases (`newline`, `tabulator`, `neue Zeile`, `neuer Absatz`, `Tabulator`, `alles groß`, ...) fire whenever the canonical keyword is enabled
- **Symbols** (opt-in via `symbols` list, German aliases such as `Schrägstrich`, `Klammer auf` fire with the English keyword): `slash`, `backslash`, `pipe`, `tilde`, `asterisk`, `open/close paren/bracket/brace`, `less/greater than` (safe defaults) + `hash`, `percent`, `dash`, `hyphen`, `plus`, `equal`, `colon`, `star` (ambiguous, disabled by default)
- **Numbers** (on by default; `numbers_as_digits = false` turns it off; a saved value is kept as is): spoken number words → digits in English and German in one pass (German first), including compounds ("twenty five" → "25", "one thousand five hundred" → "1500", "fünfundzwanzig" → "25", "zweihundertdreiundvierzig" → "243", "zwei tausend fünf hundert" → "2500"). German `ein`/`eine`/... are articles and only count directly before `hundert`/`tausend`/`Million(en)`/`Milliarde(n)`; `Million(en)`/`Milliarde(n)` need a multiplier in front
  **Ordinals** follow the same switch (off: unchanged). German: `zwölfter` → `12.`, `am zwanzigsten` → `am 20.` (`_de_ordinal_value`: cardinal + `-te` for 2-19, `-ste` for 20 and up, irregular `erste`/`dritte`/`siebte`/`achte`; `dreiste` and `einte` are not ordinals; `achte`/`achten` count only after an article or `am/im/zum...`, so the verb stays; a following full stop is not doubled; `zweitens`, `Drittel` and friends stay words; capitalised names such as `die Neunte` do become `9.`). A capitalised `Eins` opening a sentence stays a word when an ordinary word follows (`Eins ist klar`; `Eins, zwei, drei` still converts). English: `twelfth` → `12th`, `twenty first` → `21st`; a lone `first`/`second` stays a word (adverb, time unit), `one second` → `1 second`.

- **Press enter** (opt-in via `press_enter = true`, needs `enabled`): `split_press_enter()` strips a *trailing* `press enter` / `hit enter` / `Enter drücken` / `drück(e) Enter` (comma before it dropped, sentence punctuation kept) right after the dictionary, before the other voice commands and translation; `inject_text(..., press_enter=True)` sends Enter (VK_RETURN + scan code) 100 ms after the paste, or Enter alone when nothing is left (saved as `[press enter]`). Not applied to remote-mic recordings — the phone inserts the text itself

**Bilingual rule:** every spoken vocabulary (commands, numbers, anything new that matches speech) covers English and German from the start. There is no language switch in the matcher; both are always recognised, and every new feature ships with German tests.

Symbol commands do not break `all caps` mode; structural commands do. Pattern is compiled per (active symbols, active structural) pair and cached via `lru_cache`. `ALL_SYMBOL_INFO` and `ALL_STRUCTURAL_INFO` (public) are consumed by the dashboard UI to render per-keyword toggle chips (with the German aliases as tooltip data).

## Nexus OS Command Layer

**Experimental, off in v1** (`[experimental].os_commands` and `.flag_command`, both default false; see `ExperimentalConfig`). `dictation/os_commands.py` + `system/window_manager.py` — checked before voice commands. If transcription matches a nexus pattern, executes the command and skips text injection entirely.

- Window management: `"nexus <action> <app>"` — open, close, focus, fullscreen, minimize, snap left/right
- Requires `[experimental].os_commands = true`, `os_commands.enabled = true` and app registered under `[os_commands.apps]` in `config.toml`
- Force-foreground uses AttachThreadInput + Alt key trick + SPI timeout fallback (Vista+ restriction workaround)
- **"nexus flag"** needs `[experimental].flag_command = true` (independent of `os_commands.enabled`); without it the phrase is typed like any text. Flags most recent transcription for review, no DB record for the flag itself

## Assistant Forward

`dictation/assistant.py` — checked after the nexus flag/OS commands, before voice commands, only when `[assistant].enabled`. `"nexus assistant <text>"` (also `assistent`, an optional comma/colon) sends `send <service> <text>` to `host:port` over TCP, one request per connection, client shuts its write side, reply is one line. Saved to the DB as `[assistant] <text>`, nothing injected. `OSError` (nothing listening) plays `beep_error` and falls through to normal injection, so a sentence is never lost. The TCP contract, shared with `[os_control]` command recordings, is documented for users in `docs/CONTROL_PORT.md`; keep it in sync when the protocol changes.

## Translate Before Inject

`dictation/translator.py` — `translate(text, config)` runs on the processed text (after dictionary and voice commands) right before injection, only when `[translator].enabled`. It POSTs `{"text": ...}` to `[translator].url` - a local `translator` server (TranslateGemma via Ollama on 127.0.0.1:8003), which translates German sentences and passes English ones through byte for byte - and injects the reply. The transcript is saved as spoken, never translated. Any failure (nothing listening, non-200, malformed reply, timeout) logs a warning and returns the original text, so a sentence is never lost. The tray item "Translate to English (local server): ON/OFF" flips `enabled` and saves the config. `is_reachable(config)` POSTs an empty text with a 1.5 s cap; any HTTP answer counts, and the dashboard shows the result under the toggle (`/api/settings/translator-status`) so the toggle never looks self-contained. The contract is documented for users in `docs/TRANSLATOR.md`. Blocking HTTP, run in the executor like the injection. `translate()` returns a `TranslateResult` (text, translated, source, ms, error); the last four are saved on the transcription row (`translated`, `translate_source`, `translate_ms`, `translate_error`) so the dashboard overview can report how often translation ran, its average server time, and how often the fallback fired.

## Learn From Edits

`dictation/edit_watch.py` — opt-in via `[learn_from_edits].enabled` (checked per paste in `app/cycle.py`, so the dashboard toggle is live). After `inject_text`, `EditWatcher.watch(text, window_s)` hands the pasted text to one worker thread (own COM init via `system/com.py`; no COM pointer crosses threads, the hotkey hook never blocks). The worker takes the UI Automation focused element (`UiaTextField.focused()`; it raises `FieldSkipped` for `CurrentIsPassword` and for a terminal - `uia.foreground_is_terminal` / `uia.is_terminal_element`, the same lists polish uses), reads it via ValuePattern or TextPattern until the pasted text shows up (apps paste asynchronously, up to 2 s; not found → skip). The paste is found with any run of whitespace matching any other (`_find_last`), so a field that re-wraps or re-indents it still counts, then re-reads every second for `window_s` (default 20 s), keeping the last readable text. The span of the paste in the first read is found once per watch and handed to `extract_edit` and `judge` (`span=`), not searched again on every poll. A new `watch()` (the next dictation) ends the running one early; its result still counts, and when that watch raises after it took the next item (or the stop sentinel) off the queue, the worker (`_run`, `_taken`) still processes that item and still stops on the sentinel. `extract_edit(before, injected, after)` finds the paste in `before` (last occurrence, whitespace-tolerant), maps the span onto `after` through a character diff (common prefix/suffix trimmed first) — text typed right before or after the span stays outside it — and rejects deleted or rewritten spans (char similarity < 0.5). `learn()` then requires half the dictated words kept and at most 2 changed places, runs `dictionary.suggest_entries` and drops replacements over 4 words and language mix-ups (`_language_switch`: both sides two words or more, lingua's top guesses differ and one side is ≥ 0.9 sure — Parakeet sometimes hears German "jetzt aber" as "it's our", and such an entry would rewrite real English; short phrases rarely get a confident guess on both sides, so one sure side is enough). Results go to `Database.add_dictionary_suggestions` (`dictionary_suggestions` table, duplicates and existing entries skipped) — never straight into the dictionary; the dashboard accepts or dismisses them. Skipped for remote-mic pastes and for dictations auto cleanup or translation changed (`ProcessedText.learnable`). Voice commands and "press enter" no longer drop the whole dictation: `ProcessedText.spoken` (the text after the dictionary) goes along, and `learn()` keeps only entries that `apply_dictionary` would apply to it, so a fix of "25" typed for "fünfundzwanzig" is dropped while a misheard name next to a "new line" is learned. Every paste ends in one outcome (`OUTCOMES`: suggested; the watched ones that taught nothing - `unchanged`, `too_small` (only line breaks moved; a different run of spaces, a non-breaking space for instance, counts as `unchanged`), `rewritten` (dictation deleted or char similarity under 0.5), `too_many_changes`, `no_replacement`, `lost_field` (the element died before any edit was seen); the skipped ones - `failed` (the comparison or the watch itself raised: it is still recorded, so every paste ends in exactly one outcome), processed, polished (a watch cut short before any fix was seen: `App._paste_over_selection` and the paste key, for a Polish or extension reply, call `EditWatcher.pause()` before the paste - reads stop and one in flight is void - then `cancel()` once the text is in, which ends every watch handed in so far and judges the last text read *before* the rewrite, so a fix the user made earlier is still learned (`resume()` when nothing was pasted; an empty reply or one equal to the selection touches nothing)), clipboard, terminal, password, no_field, unreadable, too_long, not_found), logged at INFO with the numbers behind it (`Verdict.detail`) and how the watch ended (time window over / next dictation arrived / field unreadable), and counted in `EditWatcher.status()` (`watched` is `WATCHED_KEYS`, derived from `OUTCOMES`: every outcome whose message does not start with "skipped"; the dashboard uses it to tell watched from skipped, and it is answered without the app too). `judge()` returns the `Verdict`, `learn()` is its suggestions only. A failed read (`UiaTextField.read` keeps `last_error` and logs at DEBUG; the watcher announces a dead field at INFO once per watch, so a field rebuilt on every poll does not flood the log) makes the watcher fetch the focused element again through the one helper `_refetch(accept, stop)` (`_REFETCH_TRIES` tries of 0.2 s; also when the very first read dies, even after it saw the old text without the paste: `_read_pasted` returns `died` besides the reason, and the reason it had seen - too_long, not_found - is what gets recorded if no other element helps). For the first read `accept` is a single read that must show the paste (no 2 s wait per try). In the watch loop `stop` is the deadline or a waiting dictation, so a refetch never outlasts the window or delays the next watch. A password field or terminal met while refetching ends the first read as `password`/`terminal`; in the loop it ends the watch as unreadable. In the loop a re-fetched element is adopted only when `_still_ours` says it is the same field: not much longer than the first read (twice its length + 500 characters, else it is a page), and the paste itself is in it, or - for fields up to 2,000 characters - the whole text is still 60% similar to the first read and `extract_edit` finds the fixed dictation. The dictated words alone never decide, since a results page holds them too. Focus that moved to another field or page is never diffed, and the last successful read is what gets judged when nothing usable comes back. A dead field with a `unchanged` or `too_small` verdict is `lost_field`, since no edit was seen. Known gap, address bar of Chrome/Edge: inline autocomplete glues a completion to the last dictated word and a search rewrite replaces the words, so the words-kept filter (not the char similarity) reports `too_many_changes`; nothing is learned there on purpose. `[general].log_level` (`DEBUG`/`INFO`/`WARNING`/`ERROR`, default `INFO`, read once in `__main__`) sets the level of the `nexusvox` loggers; the root stays at INFO or above, so DEBUG does not flood the console with comtypes and urllib3; `app/cycle.py` records the outcomes it decides itself through `skip()`. The dashboard shows the last outcome and the counts since start under the toggle. Accepting a suggestion drops the other pending ones for the same `wrong`. Fields over 20,000 characters are not watched. Terminals are skipped on purpose: xterm.js (Orca, VS Code, Electron terminals) focuses an always-empty `xterm-helper-textarea`, and Windows Terminal's buffer is hard-wrapped and often over the size limit, so the paste was never found there.
