# Configuration reference

Every `config.toml` section and where its dataclass lives (`src/nexusvox/config_sections/`).

`config.toml` (git-ignored) is created in the working directory on first run, from the template at `src/nexusvox/config.example.toml`. The template ships inside the package so an installed wheel can find it; do not move it back to the repository root. Editable settings: first-run setup (`[general].setup_done`, bool: false only in the config created from the template on a fresh install, true when the key is missing, so no existing install sees the setup; the dashboard sets it when the setup is finished or skipped, and the app opens the dashboard on its own at start while it is false), dictation microphone (`[audio].device`, a device name as the dashboard lists it, empty: the system default input; `AudioCapture.start` reads it at every recording), file log (`[general].log_full_text`, bool, default false: dictated text is shortened in the file log), console log level (`[general].log_level`, `DEBUG`/`INFO`/`WARNING`/`ERROR`, default `INFO`, applied at start to the `nexusvox` loggers), injection delay (ms between modifier release and paste), hotkey modifiers, optional key, mode (`hold`/`toggle`) paste key and polish key, audio sample rate/chunk size, inference server URL, transcription model (3 entries in `MODEL_REGISTRY`: `parakeet-tdt-0.6b` (default; GPU via Docker or in-process CPU through ONNX), `whisper-large-v3-turbo` (for languages outside Parakeet's 25 European ones; Docker or in-process CPU); a config that names a removed model falls back to Parakeet on load with one log line; the dashboard model list marks each model as downloaded or not through `model_download_state`; `custom-server`, a user-run server under `[inference.custom]`: url, protocol `http`/`realtime`, model_name — no Docker, contract in `docs/CUSTOM_SERVER.md`), transcription delay, database path, audio storage directory (default `audio/`) and `store_audio` (bool, default true; off saves the transcript only), experimental features (`[experimental]`: `os_commands`, `flag_command`, `dev_tab`, all default false: hidden in v1, their dashboard endpoints not registered), OS commands enabled (bool, default false; needs `[experimental].os_commands`), OS commands apps (name→exe path mapping under `[os_commands.apps]`), assistant forward (`[assistant]` section: enabled bool, host, port, service, timeout_s), os-control command recordings (`[os_control]` section: enabled bool, command_key, host, port, service, timeout_s), voice commands (`[voice_commands]` section: enabled bool, numbers_as_digits bool (default true), structural list + bypass_structural bool, symbols list + bypass_symbols bool, press_enter bool), translate before inject (`[translator]` section: enabled bool, url, timeout_s), mic guard (`[mic_guard]` section: enabled bool, watchdog_s), dictation feedback (`[feedback].mode` `sound`/`visual`/`both`), learn from edits (`[learn_from_edits]` section: enabled bool, window_s), the language model for polish (`[llm]` section: url, protocol `ollama`/`openai`, model, api_key, timeout_s, keep_alive (default `60m`, renewed in the background while the app runs: every 5/6 of the value, `llm.renew_once` checks `/api/ps` and only a model Ollama still holds gets a load-only `/api/generate` request, nothing is ever loaded by it, and a crash leaves the model expiring on its own; a saved `"10m"`, the old default, becomes `60m` on load and is written back on the next save, any other saved value stays; sent as the number -1 because Ollama rejects the string; a value in config.toml, such as `10m`, wins. Every model the app sends a never-expire request to is noted (`llm._pinned`, before the request goes out); on quit (all of them) and when the model is switched in Settings (the old one, also through the grouped dropdown) `llm.unload` sends `keep_alive: 0` for one the app loaded itself, and `5m` (Ollama's own default) for one that was already loaded when the app first asked, so the user's session expires as before; a failed release stays noted for the next try, and a release that lands while a keep-loaded request of the same model is still in flight (a load, a warm-up or a live request, counted from before its first probe) is sent once more when the last such request ends, unless the model came back into use meanwhile (`llm.keep_in_use`, or a new warm-up); `llm.model_key` (url without trailing slash, model) is the one rule for "the same model"; Ollama protocol only); per-task models (`[llm].per_task` bool, default false: the model above does everything; only a real TOML `true` turns it on, a string such as `"false"` is logged and counts as off; `[llm].fast_tasks`, the tasks of `LLM_TASKS` (`dictation_cleanup`, `polish`, `file_cleanup`) that go to the fast model, default `["dictation_cleanup"]`, unknown names are dropped on load; `[llm.fast]`: url, protocol, model, api_key of the fast model, an empty model means none is picked and its tasks use the main model. `llm.config_for(config, task)` returns the model for a task, `llm.active_models` the main model plus the fast one when it has a task and is a different model. timeout_s and keep_alive apply to both. Warm-up at start, the renewal (which renews only active models, so a model no longer in use expires) and the release on quit cover both; a switch in the dashboard (`SettingsMixin._change_llm`) releases every model in use before and not after, whatever server or protocol replaces it, and warms up the new ones while cleanup is on. Extensions and Pro read `[llm]` itself, so they always use the main model); `[[llm.servers]]`: the custom servers saved in the dashboard, each with name, url, protocol, api_key; an entry without a URL, with an unknown protocol or a repeated URL is dropped on load, and so is an Ollama-protocol entry at `http://127.0.0.1:11434`: Ollama on this PC is a fixed dashboard entry, which also cleans up the copy an earlier version saved), polish in terminals (`[polish]` section: in_terminals bool, default false), auto cleanup (`[cleanup]` section: level `off`/`light`/`medium`, timeout_s), remote mic (`[remote_mic]` section: enabled bool, host, port, token), feedback form (`[support].feedback_form_url`: the dashboard's "Send feedback" button opens it in the browser with the app version, Windows version and hardware tier as URL parameters, `system/feedback_form.py`; defaults to `https://nexusvox.app/feedback`, an empty value hides the button; the app contacts the host only when the user clicks *Send* in the Feedback tab, and only if the URL is https on `nexusvox.app`, `system/feedback_send.py`), meeting recording (`[meeting]` section: modifiers, key, mic_device, output_device, consent_hint bool, leave_dictation_out bool, live_transcript bool, store_audio bool).
