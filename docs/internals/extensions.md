# Extensions internals

How `extensions.py` loads and guards extensions. The contract for extension authors is `docs/EXTENSIONS.md`; keep it in sync with the module. Module paths such as `app/core.py` are relative to `src/nexusvox/`; paths that start with a top-level folder (`tests/`, `docs/`, `docker/`, `scripts/`) are from the repository root.

## Extensions

`extensions.py` - optional packages register an `Extension` under the `nexusvox.extensions` entry-point group (class, instance or zero-argument factory); `ExtensionRegistry.load()` runs once at start through `load_extensions()` (started on a background thread from `NexusVoxApp.__init__`, so a heavy package never delays the hotkey, and called by `open_dashboard`, which waits for it; process-wide, idempotent, reentrant). Nothing installed means nothing changes. Everything an extension does is wrapped: an import error, a missing or taken `name`, another `api_version` (must equal `API_VERSION`, bumped only on a breaking change), a missing `api_version` (no default on purpose: a default of `API_VERSION` would be inherited after a bump), a raising `dashboard_panels()` / `export_targets()`, a malformed / duplicate panel or target id, a relative or missing `static_dir` or an export suffix / media type that is not header-safe skips the extension or the item with a log line; a raising hook becomes a job note. Nine hooks (`display_text(transcript, text)` is the seventh, `on_command` the eighth and `protect` the ninth, see below): `on_file_transcribed(FileTranscript)` runs in `DashboardAPI.upload_and_transcribe` after the save, on the job's worker thread (results land under `extensions[<name>]` in the job result, a `note` key becomes a note; the result must be a JSON-serialisable dict), `dashboard_panels()` (`DashboardPanel`: static dir served at `/ext/<id>/`, optional Flask blueprint mounted at `/api/ext/<id>/`, script registers with `NexusVoxExt.registerPanel`) and `export_targets()` (`ExportTarget`: download link per stored upload, `GET /api/file-transcriptions/<id>/export/<target>`; optional `available(id)` fills `exports_unavailable` per upload in the list and greys the link) and `upload_actions()` (`UploadAction`: a button per upload card that POSTs to an `endpoint` or calls a handler a `panel` script registers with `NexusVoxExt.registerUploadAction`). `on_dictation(text, ActiveApp)` and `on_selection_command(selection, command, ActiveApp)` (both added without an `API_VERSION` bump; `ActiveApp` = process file name + window title from `window_manager.foreground_app`) are text hooks: `ExtensionRegistry._text_hook` runs each on a daemon helper thread under one `HOOK_TIMEOUT_S` deadline for the whole chain (entry-point order; `dictation` chains the results, `selection_command` takes the first string, wired in `pipeline.process_text(extend_fn=)` and `App._polish_selection`); an exception (`SystemExit` included), a non-string result or a timeout skips that extension, and a hook still busy from a timeout is not called again. The app reaches them through `loaded_extensions()`, which returns None until the startup load is done (it never waits, so a heavy package cannot delay a dictation) and does not read the active app when nothing is installed. `on_command(text, ActiveApp) -> (label, opened) | None` (additive) is not a text hook: `ExtensionRegistry.command` calls it through `_guarded` and accepts only a `(non-empty str, bool)` tuple (anything else is logged by type and skipped), skips extensions that do not override it (`has_command_hook`), and takes its time from the same `HOOK_TIMEOUT_S` as `on_dictation` (`App._hook_budget_s`: `_extension_command` subtracts what it used, `_extend_dictation` passes the rest as `budget_s`; reset for every dictation). `App._extension_command` catches any error and returns None, so the dictation is never lost. `protect(text, ActiveApp) -> (protected, restore) | None` (additive) is how an extension keeps something through voice commands, cleanup and translation: `pipeline.process_text(protect_fn=)` calls it after the dictionary and the press-enter split (`App._protect_dictation`, also for phone dictations, where the `ActiveApp` is empty), runs the pipeline on the protected text and calls `restore` on the text to type and on the text to save before `on_dictation`. `ExtensionRegistry.protect` validates the `(str, callable)` answer like `command`, skips extensions that do not override the hook (`has_protect_hook`), chains several (restores run in reverse through one deadline) and its returned `restore(text, budget_s=)` answers None when any restore failed, was slow or did not return text; `process_text` then runs the whole dictation again without `protect` (a half-restored text is never typed or saved). `App._charged` takes the time of `protect`, each `restore` and `command` out of `_hook_budget_s` (reset at the start of every cycle, phone included), not the time cleanup and translation take between them. "nexus flag" is handled before `_run_command` and never reaches it. `display_text(FileTranscript, text)` (additive, `API_VERSION` stays 1) changes the transcript texts shown in the Upload/Meetings lists (`DashboardAPI._displayed`, only when an extension is loaded) and written by the built-in TXT/SRT/VTT exports (`builtin_export_targets(registry.display_texts)`, cue texts after `build_cues`); `ExtensionRegistry.display_texts` runs each extension over all texts in one helper thread (`_guarded`, which also holds the `_stuck` bookkeeping under a lock; `HOOK_TIMEOUT_S` + `DISPLAY_TEXT_S` per text, or a `deadline=` the dashboard shares across a whole list), a text it fails on keeps its wording, a timeout leaves all texts raw; cue texts are re-wrapped by `exports._displayed_cue` and an answer with `-->` is dropped. The `available` checks of exports and actions run through the same `_guarded` under the list's deadline. `UploadAction.available(id)` (same answers as `ExportTarget.available`) fills `actions_unavailable` per upload in the list and greys the button. Both may also answer a state dict (additive): `{"pending": label}` or `{"error": reason, "retry": action id}` (`_availability_state` cleans it; `retry` is dropped unless it is an upload action of the same extension, `_action_owner`; a skipped or timed-out check keeps the last pending state, `_last_pending`). `transcription/exports.py` holds the built-in export targets `txt`, `srt`, `vtt` (`builtin_export_targets`, registered first by `load_extensions` so extension ids cannot take them). `FileTranscript` is the frozen hook view of a `file_transcriptions` row (`file_transcript_from_record`). `DashboardAPI(extensions=)` defaults to an empty registry, so tests never see installed packages; they register a dummy `Extension` on their own `ExtensionRegistry`. Contract for extension authors: `docs/EXTENSIONS.md` - keep it in sync with the module.
