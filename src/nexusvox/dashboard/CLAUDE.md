# NexusVox — Dashboard

## Server

Flask server starts once on first tray click (left-click on the icon or the Dashboard menu item), runs in a daemon thread on `127.0.0.1:47392`. Static files in `src/nexusvox/dashboard/static/` (HTML, CSS, JS, bundled Chart.js — no CDN). API endpoints under `/api/*` return JSON, consumed by vanilla JS `fetch()` calls.

- `analytics.py` — all SQLAlchemy query functions
- `api.py` — Flask route wrappers around analytics queries
- `benchmarks.py` — benchmark JSON file I/O and cross-model comparison (Dev tab)
- `file_jobs.py` — in-memory registry of file transcription jobs (Upload tab progress)

## Look

Aurora Precision theme, shared with the website. Tokens are the `:root` variables in `style.css` (`--bg`, `--surface*`, `--border*`, `--text*`, `--accent`/`--accent-light`, `--green`, `--red`, `--orange`, 18px cards); `COLORS` at the top of `dashboard.js` reads them (and the font) from the computed style at startup for Chart.js, so `style.css` is the only place to change a color; chart-only tints are the `--accent-soft`, `--accent-fill` and `--green-fill` tokens. Geist and Geist Mono (SIL OFL) are bundled flat in `static/` (`Geist-Variable.woff2`, `GeistMono-Variable.woff2`, license in `Geist-OFL.txt`; `pyproject.toml` packages `dashboard/static/*`, so they must stay flat) - no CDN, the dashboard works offline. The `<header>` is a left sidebar (brand + stacked `.tab` buttons) and stacks above the content below 800px; `.tab` / `.tab-content` / `data-tab` are what `activateTab` in `dashboard.js` keys on, so keep them.

**No sideways scrolling, from 360px up, on every tab.** `document.documentElement.scrollWidth` must never exceed `innerWidth`. The rules that keep it so: `.setting-row` wraps (label above, control below); controls and grids use `max-width: 100%`, `min-width: 0` or `minmax(min(Npx, 100%), 1fr)` instead of a fixed minimum; `main` sets `overflow-wrap: anywhere`, inherited, so long unbroken strings (model names, paths, file names, `<code>`, status lines) wrap and flex items shrink - do not override it; a table wider than a phone sits in a `.table-wrap` (`overflow-x: auto`) and keeps `overflow-wrap: normal`. A new row, grid or table follows the same rules. There are no UI tests: check by loading the dashboard in iframes of 360, 480, 640, 800 and 1280px in headless Edge, opening every tab, with deliberately long model names and file names in the data.

## Tabs

**Analytics (tab 1)** — stat cards (transcriptions, words dictated, avg WPM with min/max, avg and longest duration, transcribe time with real-time factor, release-to-text latency, translated, minutes saved), charts (timeline, language, peak hours, latency trend, top words, heatmap) and a per-model table (`GET /api/model-breakdown`). Timing comes from `transcribe_ms` / `latency_ms` on `Transcription`, both measured from the moment recording stopped; rows written before those columns existed are skipped in the averages. The `confidence` column still exists but no backend fills it (vLLM's realtime protocol sends no logprobs), so it is not shown.

**Settings (tab 2)**
- Voice Input card: Hotkey editor (keycap display of the current binding with a `default`/`custom` badge, the default named in the text, modifier checkboxes + key select, a *Reset to default* button (disabled while on the default, `hotkey_default` in `GET /api/settings`) and a *Record* button that captures the next combo pressed in the page via `KeyboardEvent.code`; a modifier-only combo is taken on the first key-up), `POST /api/settings/hotkey` with `{modifiers: [...], key: ""}` (400 with `error` on an unusable binding, canonical modifier order and upper-case key in the reply); Hotkey Mode select (`hold` / `toggle`), `POST /api/settings/hotkey-mode`; Paste Last Text Key select (`Off` or any hotkey key name, `paste_key` in `GET /api/settings`), `POST /api/settings/paste-key` with `{key}` (400 on an unknown key, the hotkey's own key, the enabled os-control command key, or the polish key - the listener would ignore or misread those); Polish Selected Text Key select (`polish_key`, `POST /api/settings/polish-key`, same checks against the paste key) with an LLM status line (`GET /api/settings/llm-status`, probed live like the translator), a Polish In Terminals Too toggle (`polish_in_terminals`, `POST /api/settings/polish-terminals`, `[polish].in_terminals`) a Polish Model input (`llm_model`, `POST /api/settings/llm-model`; warms the new model up while cleanup is on) and an Auto Cleanup select (`cleanup_level`, `cleanup_levels`, `POST /api/settings/cleanup-level` with `{level}`, 400 on an unknown level; switching it on warms the model up in the background); the Dictation feedback card: a Sound / Visual / Sound and visual select (`feedback_mode`, `feedback_modes` in `GET /api/settings`, `POST /api/settings/feedback-mode` with `{mode}`, 400 on an unknown mode, `[feedback].mode`, live; see `src/nexusvox/CLAUDE.md`, Dictation Feedback); the Mute Other Apps While Recording toggle, `POST /api/settings/mic-guard`, and the Store Audio Recordings toggle, `POST /api/settings/store-audio` (`[database].store_audio`). All live: `HotkeyListener` reads the shared `Config` on every key event and `app.py` checks `[mic_guard].enabled` on every hold, no restart and no app bridge needed.
- Compute Device dropdown (`Auto`/`GPU (CUDA)`/`CPU`): writes `[inference].device` to `config.toml`; requires app restart. On CPU, GPU-only models are filtered out of the model dropdown server-side.
- Model switcher dropdown: for GPU-backed models, selecting stops the old Docker container, starts the new one, waits for health check, reconnects the transcriber. For in-process models (Whisper, Parakeet on CPU), just reloads the model — no Docker calls. JS polls `GET /api/models/status` every 2s for spinner/status updates; the page also checks it once on load, because Parakeet on CPU downloads its ~670 MB model on first use and `status` is then `downloading` / `loading` / `error` (from `LocalParakeetTranscriber.load_status`, via `NexusVoxApp.get_switch_status`) once no switch is in flight.
- Correction Dictionary card: add/remove entries; Learn From Edits toggle (`POST /api/settings/learn-from-edits`, `learn_from_edits` in `GET /api/settings`) with a status line under it - the last paste's outcome and the counts since start (`GET /api/settings/learn-from-edits-status`, `EditWatcher.status()` passed in as `get_learn_status`; without the app it answers no counts; refreshed every 3 s while the Settings tab is shown and the page visible, and a new `suggested` count reloads the suggestion list) and the pending suggestions learned from edits after a paste, each with Add (`POST /api/dictionary/suggestions/<id>/accept`) and dismiss (`DELETE /api/dictionary/suggestions/<id>`).
- Snippets card: trigger input, multi-line text and an options box (`name = text` per line), Add/Save (`POST /api/snippets` with `trigger`, `expansion`, `options` as `[{name, text}]` parsed from the text box in `dashboard.js`, `id` set to edit: `Database.update_snippet`, else `add_snippet`, which replaces a snippet with the same trigger), *Fill from GitHub* (`GET /api/snippets/github-repos`, runs `gh repo list`, appends `name = url` lines), per-row Edit and remove (`DELETE /api/snippets/<id>`); a trigger already used by another snippet is rejected, and a snippet needs a text or at least one option.
- Polish Presets card: name, instruction and a *Default when nothing is said* checkbox, Add/Save (`POST /api/polish-presets` with `name`, `instruction`, `is_default`, `id` set to edit; 400 when the name is taken (any case, Unicode case-folded), has more than 5 words (the spoken matcher scores 5) or a field is blank; making one the default clears the old default), per-row Edit and remove (`DELETE /api/polish-presets/<id>`).
- Meetings card: one input, *Meetings: name for your own voice* (`meeting_own_voice_label` in `GET /api/settings`, `POST /api/settings/meeting-own-voice-label` with `{label}`, `[meeting].own_voice_label`, default `Speaker 1`; whitespace collapsed, 40 characters, empty = default; 400 with `error` for `Speaker 2`..., the label other participants get).
- Nexus OS Commands card: toggle enable/disable, lists supported actions and registered apps.
- Voice Commands card: master enable/disable toggle; Numbers as Digits toggle; Press Enter Command toggle (`POST /api/voice-commands/press-enter`); Bypass Structural Commands toggle + structural command chips (`new line`, `new paragraph`, `tab`, `all caps`; `POST /api/voice-commands/structural`); Bypass Symbol Commands toggle + symbol command chips (click to activate/deactivate individual symbols, persisted immediately via `POST /api/voice-commands/symbols`).

**Edit (tab 3)** — flagged transcriptions with editable correction textarea and audio playback. Saves via `POST /api/flagged/<id>/correct`. Audio served via `GET /api/audio/<tid>`.

**Meetings (tab 4)** — Start/Stop button with a timer (`GET /api/meetings/status` every 3 s while the tab is shown, the page counts seconds in between) and a red indicator; Start shows the in-page consent hint ("Inform all participants before you record", *Don't show this again* sets `[meeting].consent_hint` off; never a browser dialog) unless it is off; Stop (`POST /api/meetings/stop`) starts the transcription job and the tab polls `GET /api/file-transcribe/<job_id>` for the progress bar. Meeting hotkey editor (modifier checkboxes + key, `POST /api/settings/meeting-hotkey`, 400 with `error` on an unusable one), microphone and output device selects (`GET /api/meetings/devices`, `POST /api/settings/meeting-devices`, empty = system default), consent hint toggle (`POST /api/settings/meeting-consent-hint`), *Leave dictation out of the meeting transcript* toggle (`POST /api/settings/meeting-leave-dictation-out`, `meeting_leave_dictation_out` in `GET /api/settings`, `[meeting].leave_dictation_out`). *Recorded, not yet transcribed* (`GET /api/meetings/pending`, hidden when empty) lists recordings without a transcript with Transcribe (`POST /api/meetings/pending/<name>/transcribe`, 409 while another file is transcribing) and Delete (`DELETE /api/meetings/pending/<name>`, in-card confirmation; only folders `meeting-*` holding `meeting.json` that are neither recording nor transcribing, else 404). The progress poll treats a vanished job (404) as lost contact, never as success. *Previous Meetings* is the file-transcription list narrowed to `?kind=meeting` (audio player, Delete). See `src/nexusvox/CLAUDE.md`, Meeting Session.

**Upload (tab 4, after Meetings)** — drag-and-drop file upload (WAV, MP3, FLAC, OGG, WebM; max 25 MB) with transcription history list. Choosing or dropping a file only selects it (`selectUploadFile`): the drop zone turns solid green with "Ready to transcribe" (`.has-file`) and `#upload-selected` shows a row with the file name, size and, once the browser has read its metadata, the duration, plus a remove button (`#upload-remove`, disabled while a job runs, which also ignores a new pick or drop; focus moves to *browse* afterwards) that restores the empty state; the *Transcribe* button (`#upload-transcribe`) starts a job, is disabled until a file is selected and while a job runs (`uploadRunning`), and the options are read at the click. A successful file is deselected; a failed one stays selected for another try. **Progress:** `POST /api/file-transcribe` only checks the file (extension, size; 400 on a bad one) and starts a background job, answering 202 `{ok, job_id}` at once; a second upload while a job runs is a 409. `FileJobs` (`file_jobs.py`, one per `DashboardAPI`, in memory, last 10 finished jobs kept, one running job at a time, no queue) runs `upload_and_transcribe(job=)` on a daemon thread; the stage comes from `FileJob.update(stage, current, total)`: `converting`, `transcribing` (chunk i of n, from `transcribe_file(on_progress=)`), `diarizing` (only when the chunks are done and speaker detection still runs), `cleaning` (passage i of n, only with text cleanup) and `saving`. `GET /api/file-transcribe/<job_id>` returns `{job_id, filename, state: running|done|error, stage, current, total, message, percent (0..1), result, error}`: `result` is what the upload returned (`id`, `text`, `notes`, ...), `error` the message of a failed one (conversion, transcription, saving; a failed save is `Saving the transcript failed: ...`; any other exception in the worker is `Unexpected error: ...`). `GET /api/file-transcribe/current` returns `{job}`: the latest job while it runs, or when it ended and no client has read how yet (reading a finished job through either endpoint marks it read, atomically under the job's lock, so of two clients exactly one gets the unread outcome), else `{job: null}`. The JS (`trackUploadJob`) polls the job every second (a failed poll is retried 5 times in a row, then the page says it lost contact and the job runs on), shows `#upload-status-text` (file name and stage) and the `#upload-progress-bar`, and on done/error shows the note, the error or the refreshed history as before; `resumeUploadJob` runs when the tab opens, when the page becomes visible again and every 3 s while the Upload tab is shown and no job is tracked, so a page reloaded mid-job, or a job started from another browser tab, shows up (and the Transcribe button stays disabled), and one that ended meanwhile shows its note or error once. A job keeps running when the page is closed, the app's exit ends it. The test database must be a file, not `:memory:`: the worker thread opens its own connection. Conversion + transcription logic in `file_transcribe.py`; 60-second chunking to avoid GPU OOM; results in `file_transcriptions` SQLite table (`FileTranscription` model in `models.py`). No voice commands or text injection for file transcriptions. With Parakeet (`word_timestamps` in `MODEL_REGISTRY`) an upload also asks the server for per-word timing; `transcribe_file(..., word_timestamps=True)` (only the upload passes it; Review Retry does not) shifts each chunk's words by the real length of the audio before it, the joined list is stored as JSON in `file_transcriptions.words` (NULL for other engines), and a chunk that timed out or came back without words is logged and returned as `notes` in the job's `result`, which the upload tab shows in its own non-error `#upload-note` box (the upload is saved); Review Retry saves nothing, so a note there fails the retry with the note as the error. A *Detect speakers* toggle between the drop zone and the button (off by default) adds `diarize=1` to the upload FormData; `refreshDiarizeToggle` reads `diarization` from `GET /api/models/current` when the tab opens, when the page becomes visible again and right before each upload (the model can change in another browser tab or the config), and disables the toggle otherwise, with the hint "Requires <names from `diarization_models`> as the active model". A checked toggle is still sent when the model changed meanwhile, so the job's note says why there are no speakers. The flag goes through `upload_and_transcribe(diarize=)` to `transcribe_file`; the labelled `Speaker N: ...` paragraphs are the saved `text` (shown with `white-space: pre-wrap`, `.upload-text`) and each stored word gets `speaker`. A problem with speaker detection is a note, the upload still saves. A *Clean up text* toggle with a Light/Medium select (`#upload-cleanup-toggle`, `#upload-cleanup-level`, off by default, read at the click) adds `cleanup=light|medium` to the FormData; anything else is no cleanup. After transcription `upload_and_transcribe(cleanup_level=)` runs `file_cleanup.clean_transcript` over the transcript (see src/nexusvox/CLAUDE.md, Upload Cleanup): `text` and the word timings stay as transcribed, the cleaned text goes into `file_transcriptions.cleaned_text` (+ `cleanup_level`; both NULL when cleanup was off or changed nothing; added by the migration in `Database._migrate`). `GET /api/file-transcriptions` and the job's `result` carry `cleaned_text`; the history card shows the cleaned text by default and a *Show original* / *Show cleaned* button (`.upload-view-switch`) flips it. A passage the model failed on keeps its wording and the job notes it (`Text cleanup could not clean N of M passages ...`), the upload still saves. Every upload offers built-in TXT, SRT and VTT downloads (`exports.py`, registered through the export-target mechanism by `ExtensionRegistry.add_builtin_exports` before the extensions load); SRT/VTT cues come from the stored word timings (at most 2 lines of 42 characters and 7 s, a new cue at a pause of 1 s, a speaker change or a sentence end, `Speaker N:` on the first cue of each turn, the stored label of speaker 1 for meetings), and an upload without word timing answers the download with a message (500 `error`). **Delete:** every history card (uploads and meetings, in both lists) has a Delete button; it turns into an in-card "Delete this ...? This cannot be undone." with Delete / Cancel (`askDeleteFileTranscription`, never `confirm()`), then `DELETE /api/file-transcriptions/<id>` removes the row and the audio files (an upload's stored audio, a meeting's whole folder; a missing file does not block it; 404 for an unknown id, 500 with `error` when a file cannot be removed).

**Extension tabs** - an installed extension (`src/nexusvox/CLAUDE.md`, Extensions; contract in `docs/EXTENSIONS.md`) may add tabs and export links. On `DOMContentLoaded` `loadExtensions()` reads `GET /api/extensions`, appends a `.tab` button (`data-tab="ext-<id>"`) and an empty `.tab-content` section per panel (`bindTab` wires the click, `activateTab` calls `openExtensionPanel`), and keeps the export targets for the Upload history, where each upload gets a `.upload-export` download link per target; the hash restore waits for it. The panel's script is added on first open and draws through `NexusVoxExt.registerPanel(id, container => ...)`. With nothing installed the page shows no extra tab; the built-in TXT/SRT/VTT export links are always there, so a non-empty `exports` list does not mean an extension is installed. An upload action with an `available` check is greyed out with its reason as tooltip (`actions_unavailable` per row), and `text`/`cleaned_text` in the list pass through the extensions' `display_text` hook (the job `result` and the stored row stay raw). SRT/VTT are greyed out (`exports_unavailable`, tooltip `NO_TIMING_HINT`) for a row without stored word timing; TXT is the text as shown (cleaned when cleanup ran) while the subtitles use the words as transcribed. The panel blueprints are mounted by `_create_app` (a mount failure is logged, the dashboard stays up), and `upload_and_transcribe` adds `extensions` (per-extension results, `{}` when none) to the job `result`.

**Review (tab 5)** — unreviewed recordings that have audio files, oldest first. Each card has *Retry* (`POST /api/review/<tid>/retry`): the stored WAV is transcribed again with the current model (same path as file upload, `transcribe_file`) and the result goes into the correction box; nothing is saved until the user submits. It needs the WAV, i.e. `[database].store_audio`, which the tab says. Users confirm correctness via checkbox or provide corrected text. Flagged-but-unreviewed items highlighted red with checkbox defaulting to incorrect. `reviewed` column on `Transcription` is tri-state: `0`=unreviewed, `1`=correct, `2`=incorrect.

**Dev (tab 6, dev-only)** — hidden unless `?dev` query param is present. Reads benchmark JSON files from `benchmarks/` directory. Two views: comparison mode (table + WER bar chart + RTF bar chart across all benchmarks) and detail mode (WER distribution histogram, latency scatter plot, sample explorer with word-level diff). WER targets from roadmap: EN <8%, DE <12%. Orange accent distinguishes from production tabs. Backend logic in `benchmarks.py`.
