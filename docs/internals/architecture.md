# Architecture

One dictation from the hotkey to the typed text, and the services around it. Diagrams: `docs/architecture.html`, `docs/text-pipeline.html`.

Hotkey listener (pynput low-level hook; default Ctrl+Win, any modifiers optionally ending in one key under `[hotkey].key`, whose keystrokes are swallowed while held as part of the combo; `[hotkey].mode` = `hold` push-to-talk or `toggle` press-to-start/press-to-stop; `[hotkey].paste_key` (default `V`) tapped during a recording drops it and pastes the last pasted text again; `[hotkey].polish_key` (default off) makes the recording a spoken instruction for the selected text, rewritten by a local language model (`dictation/polish.py`, `llm.py`, `[llm]`: Ollama by default; a spoken preset name from `polish_presets` in SQLite stands for its stored instruction, `dictation/polish_presets.py`); binding and mode switchable live in the dashboard) triggers microphone capture (sounddevice, 16kHz PCM16 mono) and, when `[mic_guard]` is enabled, mutes every other app's WASAPI capture session for the duration of the hold (`audio/mic_guard.py`); the audio streams to a transcription backend (HTTP POST for Parakeet and Whisper, HTTP or WebSocket for a custom server). A recording marked as a command - `[os_control].command_key` (default `Y`, so Ctrl+Win+Y; `OEM_102` for the `<` key) pressed during a recording while every hotkey modifier is down, and swallowed (without the full chord it types normally) - is never typed: its transcript goes to the Controller as `send os-control <text>` (`::show` already goes out on the key press, from a thread so the hook never blocks; `::hide` instead of the text when the transcript is empty, and also when the cycle is skipped or fails), is saved as `[os-control] <text>`, and an unreachable port or an `error:` reply plays the error beep. Every other transcribed text passes through a nexus OS command check, then the assistant forward (`dictation/assistant.py`: "nexus assistant <text>" is sent to a local TCP port as `send <service> <text>` and not typed; unreachable port falls back to typing), then the correction dictionary (`dictation/dictionary.py`, entries in SQLite, edited in the dashboard), then optional voice command processing, then optional auto cleanup (`dictation/cleanup.py`, `[cleanup].level` `light`/`medium`: the [llm] model drops fillers and fixes punctuation; an implausible reply or any failure types the text unchanged), then optional translation into English (`dictation/translator.py`: a local HTTP translator server; unreachable server falls back to the original text), then is injected at the cursor (with `[feedback]` the cycle is signalled by chimes, a click-through waveform overlay at the bottom centre of the screen (`dictation/overlay.py`), or both) via clipboard + SendInput (Ctrl+V) with WM_PASTE fallback (`dictation/clipboard.py` keeps those clipboard writes out of the Win+V history), and saved to SQLite as spoken, before translation. Commands (an extension's `on_command`, nexus flag, assistant, nexus OS commands) are dispatched by `App._run_command`; everything from the dictionary to translation (cleanup included) is the pure function `pipeline.process_text`, which returns what to type, what to save and whether the paste can be learned from; an extension's `protect` hook shields parts of the text (also for phone dictations) before voice commands and its `restore` undoes that after translation. With `[learn_from_edits]` enabled, `dictation/edit_watch.py` then reads the focused field through UI Automation for a while and turns the words the user corrects there into pending dictionary suggestions (accepted in the dashboard). With `[remote_mic]` enabled (and a token set), `audio/remote_mic.py` serves a WebSocket on port 47393 (`/v1/remote-mic`, `Authorization: Bearer <token>`): a phone sends `start`, PCM16 frames and `stop`, and the cycle runs with `RemoteAudioSource` in place of `AudioCapture` (`_transcription_cycle(remote=True)`: never a command recording, no nexus/assistant actions, hotkey ignored meanwhile; the processed text is not injected but sent back in `done` for the phone to insert); contract in `docs/REMOTE_MIC.md`. A Flask dashboard on port 47392 provides analytics, settings, flagging/review, and file upload transcription (optional speaker detection with Parakeet: `transcription/diarization.py`, the container's `/v1/audio/diarization`). System tray (waveform mark, red while recording) opens the dashboard on left-click; the right-click menu has translate toggle, dashboard, and quit. The dashboard opens on a Home tab (model status, dictate hotkey, record a meeting, transcribe a file, the newest recordings, this week). The Settings tab is grouped into Dictation (hotkey with a Record button, mode, feedback, mic guard), Text & Polish (paste and polish keys, auto cleanup, translation, voice commands), Vocabulary (dictionary, polish presets), Models, Meetings, Privacy and a collapsed Advanced card (compute device, polish in terminals, polish model, OS commands).

*Module paths in this file (`app/core.py`, `system/feedback_form.py`) are relative to `src/nexusvox/`; paths that start with a top-level folder, such as `docs/REMOTE_MIC.md`, are from the repository root. The package layout and its rules are in `src/nexusvox/CLAUDE.md`; the dashboard's in `src/nexusvox/dashboard/CLAUDE.md`; CI/CD and releases in `.github/CLAUDE.md`. Per-module detail is in the other files of `docs/internals/`.*
