# Transcription internals

Transcribers, the realtime protocol, speaker detection and the file-upload transcript cleanup. Rules: `src/nexusvox/CLAUDE.md`. Wire contract for custom servers: `docs/CUSTOM_SERVER.md`. Module paths such as `app/core.py` are relative to `src/nexusvox/`; paths that start with a top-level folder (`tests/`, `docs/`, `docker/`, `scripts/`) are from the repository root.

## Transcriber Architecture

`BaseTranscriber` ABC (`needs_docker: bool = True` class attr) with a factory pattern. Four implementations (plus the auto wrapper below):

- **`VoxtralRealtimeTranscriber`** — streams audio chunks over WebSocket to a vLLM-style `/v1/realtime` endpoint; no bundled model uses it any more (Voxtral was removed), it is the client for a `custom-server` with `protocol = "realtime"`
- **`OpenAIHttpTranscriber`** — buffers audio in memory, POSTs a WAV file to an OpenAI-compatible `/v1/audio/transcriptions` HTTP endpoint (used by Parakeet TDT, GPU-backed Whisper and a custom HTTP server). Dictation sends only `file` and `model`. `supports_word_timestamps` (class attr on `BaseTranscriber`, True here) says the client can; `transcribe_file(word_timestamps=True)` sets `word_timestamps = True` when the model's registry entry also has `word_timestamps` (Parakeet only), which adds `response_format=verbose_json` and `timestamp_granularities[]=word`; `docker/parakeet_server.py` then also returns `words` (`{word, start, end}` in seconds) and `TranscriptionResult.words` holds them. Engines without timing leave it empty. `supports_diarization` (True here) plus the registry's `diarization` flag (Parakeet only) let `transcribe_file(diarize=True)` call `diarize(wav, timeout)`: the whole file (bytes or a file object) is POSTed once to `/v1/audio/diarization` next to the transcription URL (`diarization_url`), and the reply `{segments: [{speaker, start, end}]}` becomes `SpeakerTurn`s (`parse_turns`)
- **`LocalWhisperTranscriber`** (`transcribers/local_whisper.py`) — in-process faster-whisper, no Docker. Class-level `_model_cache` keeps loaded models warm across switches. `needs_docker = False`. Blocking `WhisperModel.transcribe()` runs in `loop.run_in_executor` to keep the asyncio loop responsive.
- **`LocalParakeetTranscriber`** (`transcribers/local_parakeet.py`) — Parakeet TDT 0.6B v3 on CPU through `onnx-asr` (`nemo-parakeet-tdt-0.6b-v3`, `quantization="int8"`, ONNX Runtime CPU provider, ~670 MB from `istupakov/parakeet-tdt-0.6b-v3-onnx` on first use). Same shape as the Whisper one: class-level `_model_cache`, background load on `connect()` (`_begin_preload`: one at a time, set to `loading`/`downloading` before the thread starts, none after a failed load - the next `finish()` makes the one retry, and a new transcriber clears the error), `needs_docker = False`. Recognition runs on the class's own single-thread executor, so jobs queue there and not in the default pool; `finish()` sets a `cancelled` event on timeout, which makes a queued or running job stop (between segments) instead of working on a result nobody reads, and resets the buffer even when a load or ONNX error propagates. The registry entry carries `inprocess_engine: "parakeet-onnx"` (plus `onnx_model`, `onnx_quantization`) next to `inprocess_supported: True`, which is how `create_transcriber` tells it from Whisper; on GPU the same entry is still the Docker NeMo container. Audio up to `MAX_DIRECT_S` (20 s) goes to the model in one call; longer audio (long dictations, a 60 s upload chunk) is cut by `split_at_pauses` (energy-based, no VAD model) into segments of `MIN_SEGMENT_S` (6 s) to `MAX_DIRECT_S` at the longest pause in the window (a small bonus for later cuts), at the quietest frame when a window holds no pause, and each segment is a plain `model.recognize` call like a short dictation (onnx-asr's Silero VAD cut short pieces without context and the output drifted into other languages); segments that are silent (peak below `_SILENCE_PEAK`) are skipped, the texts are joined. Benchmark: `scripts/parakeet_long_bench.py` (raw WER and WER after `process_text`). Word timing (`word_timestamps`, set by `transcribe_file`) comes from the token timestamps: `words_from_tokens` opens a word at every token that starts with the SentencePiece mark (onnx-asr already turns `▁` into a space, both are accepted), so punctuation stays on its word, also when its token carries the mark (onnx-asr drops the space before a non-word character in the text, the words follow it); a word runs from its first token to one frame (`FRAME_S`, 80 ms) after its last, capped at the next word; segment words are shifted by the segment start. `supports_diarization` stays False: speaker detection lives in the Parakeet container, the engine carries `no_diarization_reason` ("Speaker detection needs the GPU container"), and both `get_current_model` (`diarization: false` + `diarization_hint`, read from the running transcriber through the `get_transcriber` callback, never from the device setting) and an upload that asks for speakers (a note) take it from there. `load_status()` (`idle`/`downloading`/`loading`/`ready`/`error`, lock-free because `_get_model` holds `_cache_lock` for the whole download) reaches the dashboard through `NexusVoxApp.get_switch_status` whenever no switch is in flight (idle or just ready: `downloading`, `loading`, or `error` with the reason); `_preload_transcriber` runs at start and after a switch to any in-process model.

- **`AutoParakeetTranscriber`** (`transcribers/auto_parakeet.py`) - engine "auto" (`[inference].device = "auto"`) with Parakeet on a CUDA machine: `create_transcriber(..., auto_fallback=True)` returns it instead of the plain server client (callers pass `config.device == "auto"`; an explicit `cuda`/`cpu` never gets it). It wraps `OpenAIHttpTranscriber` (GPU) and a lazily built `LocalParakeetTranscriber` (CPU). The engine comes from a health probe of the *configured* server (`health_url_for`: the registry's `/health` path on the host and port of `[inference].server_url`, `localhost` -> `127.0.0.1` because `localhost` also tries `::1` first on Windows), `PROBE_TIMEOUT_S` 0.5 s. A daemon monitor thread (started by `warm_up`, holds only a weak reference so a switched-away engine ends it) probes every `PROBE_TTL_S` (3 s), so `connect()` never waits for a probe after the first one and a server that comes back is used within seconds, no restart; without a monitor `prepare()` (a no-op on `BaseTranscriber`, called by `transcribe_file` before it reads the capability flags) refreshes an answer older than the TTL. `connect()` pins the engine for the whole cycle (`_cycle`), so a flip mid-take cannot split it. The GPU path keeps a copy of the cycle's audio: when `finish()` raises or returns a result that is not `done` (the client swallows a timeout, so a hung server), the engine is marked CPU and the audio is replayed through the CPU engine, so the take is not lost. The GPU is chosen only when the server is reachable *and warmed up*: a server that has just become reachable (also at start, and after any outage) is cold (first request ~17 s), so `_apply` keeps the CPU engine and starts one background warm-up request (`_run_warm_up`, a silent clip through a client of its own; a failure is retried by the next probe, and a result is void if the server was seen down meanwhile, `_generation`), and logs the switch to the GPU when it succeeded. A dictation during that time goes to the CPU. The monitor's health GETs are dropped from the `httpx` INFO log by `_HealthProbeFilter` (state changes are logged by `_apply`; the POST lines stay). Going to CPU starts the CPU model load in the background (`_preload_cpu`), so a later take does not pay a 670 MB load inside the `finish` timeout. `needs_docker`, `supports_diarization`, `no_diarization_reason`, `model` and `load_status()` follow the engine (`needs_docker` False on CPU, so a model switch does not try to stop a profile when Docker is down); meetings and uploads skip speaker detection on the CPU path exactly as on a CPU-only machine. `warm_up()` (`BaseTranscriber.warm_up` = connect + disconnect; `warms_up_at_start` is the class flag `App._warms_up()` checks at start and after a model switch) sends 0.5 s of silence through a client of its own (measured 17 s cold; a dictation during it keeps its buffer) or lets the CPU model load; it never raises and runs as a background task. The engine is logged on every change.

`create_transcriber(config, *, device, auto_fallback)` dispatches:
- `custom-server` (registry flag `custom`) → `_create_custom_transcriber`: `[inference.custom].protocol` `http`/`realtime` picks `OpenAIHttpTranscriber`/`VoxtralRealtimeTranscriber` on `[inference.custom].url`, with `model = model_name` and `needs_docker = False` set on the instance. Empty url raises. `[inference].server_url` is not touched. `model_needs_docker()` in `config_sections/inference.py` is the single Docker decision for `switch_model`; a failed switch restores the old model and URL in the config. The wire contract users implement is `docs/CUSTOM_SERVER.md`; keep it in sync with both transcriber classes.
- CPU + `inprocess_supported=True` → `LocalParakeetTranscriber` when the entry has `inprocess_engine: "parakeet-onnx"`, else `LocalWhisperTranscriber`
- Otherwise → protocol-based dispatch (`realtime_ws` or `openai_http`)

Device resolution: `resolve_device("auto")` probes `ctranslate2.get_cuda_device_count()`. CTranslate2 ships with faster-whisper, so no extra detection dep. Active model set in `config.toml` under `[inference].model`; device under `[inference].device` (`auto`/`cuda`/`cpu`). Both switchable at runtime via the dashboard.

## Realtime Protocol (custom servers)

The WebSocket protocol requires a specific commit sequence:

1. Receive `session.created` from server
2. Send `session.update` with model name
3. **Send non-final `input_audio_buffer.commit`** — this starts the generation engine
4. Send `input_audio_buffer.append` chunks (base64 PCM16)
5. Send `input_audio_buffer.commit` with `final: true` — signals end of audio

Without step 3 the server never starts processing audio.

**Logprobs are not available** in the realtime WebSocket protocol. The `transcription.done` message only returns token counts in the `usage` dict (`prompt_tokens`, `completion_tokens`, `total_tokens`). The `transcription.delta` messages only contain `type` and `delta` (text). Confidence extraction code exists in `TranscriptionResult` and will activate automatically if vLLM adds logprob support.

## Speaker Diarization (file uploads)

`transcription/diarization.py` — pure merge logic. `transcribe_file(..., diarize=True)` (implies word timestamps) starts speaker detection as a task (`_diarize_file`) **before** the 60 s chunks are transcribed, since it does not need the transcript: the whole file goes to the server **once**, so speaker indices stay the same across chunks. The WAV is written straight from `wav_chunks` into one `BytesIO` (`_whole_file_wav`, no second PCM copy) and handed to httpx as a file object. `_DIARIZE_LOCK` (process-wide, polled so a cancelled task never holds it) lets one speaker request at a time leave this app, and the timeout `diarization_timeout(duration_s)` (300 s base for loading or first downloading the model, plus 0.5 s per second of audio) starts only after the lock is taken, so a second upload never spends its timeout waiting behind the first; chunk calls keep their 120 s. A failed transcription cancels the task. `label_words` gives each word the speaker whose turn holds its midpoint (overlapping turns: the one covering more of the word; a word in no turn: the nearest turn) and numbers speakers 1, 2, ... in order of first appearance; `format_transcript` joins consecutive words of one speaker into `Speaker N: ...` paragraphs separated by a blank line, which become the saved and returned text, and each stored word carries `speaker`. The labelled text is built from the words, so labelling is skipped (plain transcript plus a note) when any chunk returned fewer timed words than its text has words (the server drops a word whose timing it cannot read); a timed-out chunk does not block it, its text is missing from the plain transcript too. A model without the `diarization` flag (the note names the flagged models via `speaker_detection_models()`), a client without `supports_diarization`, a failed request (timeout, server down) and an empty turn list also return the plain transcript with a note, never an error. `diarization_url` maps `.../transcriptions` to `.../diarization` and any other URL to `/v1/audio/diarization` on the same host.

Server side (`docker/parakeet_server.py`): `nvidia/diar_streaming_sortformer_4spk-v2` (CC-BY-4.0, at most 4 speakers) is loaded on the first diarization request only, into CPU memory and outside the GPU lock (the first download does not stall dictation), with the model card's "very high latency" streaming preset. `_gpu_lock` puts one model on the GPU at a time: transcriptions now run in the thread pool (`run_in_threadpool`, so waiting never blocks the event loop and `/health`) and take the lock; a diarization run takes it, moves Sortformer to the GPU, and afterwards back to the CPU plus `torch.cuda.empty_cache()`, so VRAM returns to the Parakeet-only level. A dictation that arrives during a run waits for it (a 10-minute file takes ~2.4 s). Loading Sortformer also turns off Parakeet's CUDA-graph decoder (`_disable_cuda_graph_decoding`): with graphs captured before a Sortformer run, the next transcription dies with "CUDA error: an illegal memory access" and takes the container down (reproduced with plain request order transcribe → diarize → transcribe, independent of the CPU offload and the lock). Graphs off costs ~35 ms per 5 s dictation and ~130 ms per 30 s, so they stay on until the first diarization request. It needs NeMo ≥ 2.5 (`spkcache_update_period`); `docker/Dockerfile.parakeet` pins 2.7.3 and uninstalls the base image's `nvidia-modelopt`, which fails to import with the newer transformers NeMo brings.

## Upload Cleanup (file uploads)

`file_cleanup.py` — optional LLM cleanup of an uploaded file's transcript (dashboard *Clean up text*, level `light`/`medium`), reusing `cleanup.cleanup()` with its prompts and `plausible()` check; no prompt of its own. The pieces are slices of the transcript itself, with the whitespace between them kept, and a transcript in which no piece changed comes back byte for byte (so a dead model never stores a whitespace-only "cleaned" version). `split_paragraphs` cuts the transcript at blank lines (the `Speaker N: ` label of a diarized block is split off, never sent to the model and put back) and `split_pieces` cuts each block at sentence ends into pieces of at most `MAX_WORDS` (120) words (a sentence longer than that is cut after a comma, semicolon or colon in its second half where there is one, else by words; a full stop after "Dr.", "z. B.", "bzw." and similar does not end a sentence), so a cut rarely lands mid-clause and invites a false sentence break from the "fix punctuation" prompt, because a small model loses the thread on a long monologue and a transcript without speakers is one long block. Each piece is one `cleanup()` call with `CleanupConfig(timeout_s=[llm].timeout_s)`, not the 3 s dictation timeout. A piece the model fails on, answers implausibly or leaves alone keeps its own words, so the cleaned transcript is always complete. After `MAX_CONSECUTIVE_FAILURES` (3) `LlmError`s in a row the remaining pieces are skipped (a server that is down would otherwise cost the full timeout per piece); only a piece the model actually answered resets the streak (a piece too short to send does not), and an implausible reply counts as an answer. Pieces under `MIN_PIECE_WORDS` (2) words are not sent (dictation skips under 3: `cleanup(min_words=)`), so a turn like "um hi." is cleaned and a single word is left alone. The requests run inside `llm.background()`: `llm.complete` counts live requests (dictation cleanup, polish) and a background request waits, up to `BACKGROUND_WAIT_S` (30 s), until none runs, so a live request waits behind at most the one piece already in flight, not behind the whole upload. `TranscriptCleanup.note` says how many passages stayed as spoken and becomes a job note. The result is stored beside the raw transcript; the transcript and its word timings stay untouched. English and German go through the same prompts; both are covered in `tests/test_file_cleanup.py`.
