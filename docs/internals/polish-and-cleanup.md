# Polish and auto cleanup

The two features that send text to the `[llm]` model. Module paths such as `app/core.py` are relative to `src/nexusvox/`; paths that start with a top-level folder (`tests/`, `docs/`, `docker/`, `scripts/`) are from the repository root.

## Polish

`dictation/polish.py` + `llm.py` — the polish marker key makes the recording an instruction for the selected text. After the transcript arrives, `App._polish_selection` reads the selection with `polish.read_selection`: first `uia.read_focus` asks the focused control through UI Automation (TextPattern `GetSelection`; no key sent, clipboard untouched; an empty reported selection counts as nothing selected). A terminal (Windows Terminal, console host, mintty, ConEmu, PuTTY by window class; xterm.js and `TermControl` by focused element) gets **no** Ctrl+C by default - with nothing selected it would interrupt the running program - and polish beeps; `[polish].in_terminals` (dashboard toggle, read per polish) lets a terminal get Ctrl+C like any other control, and the reply is then pasted at the prompt (a terminal's selection is in its output, not editable). Only a control that does not report its selection falls back to `injector.copy_selection` (clipboard emptied, Ctrl+C via the shared `_send_ctrl_chord`, polled up to 1 s, original clipboard put back; `injector` is imported inside `read_selection` because it binds Win32 at import). A quick tap of the polish chord (released before recording started) polishes with the default instruction; its row has no audio and duration 0. A polish or extension attempt is saved as `[polish] <name>` (`[extension] ...`) when the reply was pasted and as `[polish failed] <name>` when it was not (model failed or timed out, focus moved, clipboard refused); `polish_status`/`polish_ms` go with it and the row is kept out of every dictation statistic (`analytics_common._apply_date_filter`). A polish key equal to the paste key in `config.toml` is dropped on load. The spoken instruction goes through `polish_presets.resolve_instruction` first: a preset name at its start (`polish_presets` table, edited in the dashboard; matched with `snippets.best_option`, the fuzzy name matcher, so case, spaces, hyphens and close spellings do not matter) is replaced by the preset's instruction, with the words after the name appended as `Also: ...`; nothing said uses the preset marked default (at most one, enforced in `Database.save_polish_preset`). The row is saved as `[polish] <preset name>` then. Presets are user-defined only, so the bilingual rule is met by the user. No language is sent to the speech model (the language setting went in #195), so a short instruction can come back in another script (the preset name "Brief" as Cyrillic "Бриф."): before the preset lookup, `polish_presets.unexpected_script` checks the letters of the instruction, and when most of them are in a script that is neither Latin (English and German) nor used by a saved preset name, nothing is polished (error beep, selection untouched, no history row) and the log says `Polish: instruction in <SCRIPT> script, not used (<n> characters)` without the text. It then sends selection + instruction (or `DEFAULT_INSTRUCTION` when nothing was said and there is no default preset) to the model and pastes the reply over the still-selected text (`inject_text`, so Ctrl+Z in the app undoes it); saved as `[polish] <instruction>`, and `_last_typed` becomes the reply. The reply keeps the selection's leading/trailing whitespace (a selected line keeps its newline) and loses a leading `<think>` block (protocol `openai` cannot turn thinking off). If the foreground window changed while the model worked, nothing is pasted (error beep); the paste key still pastes the reply. Nothing selected, `LlmError` (server down, timeout, empty or malformed reply) or `ClipboardError` → error beep, selection untouched. A password field (`CurrentIsPassword`) counts as nothing selected, and so does a selection that reaches the 100,000-character `GetText` cap - the reply would be pasted over text the model never saw. `llm.complete` speaks Ollama's `/api/chat` (`think: false` for reasoning models, `keep_alive`) or OpenAI-compatible `/chat/completions` (`protocol = "openai"`, optional Bearer `api_key`; the body carries `chat_template_kwargs: {enable_thinking: false}`, which llama.cpp's server reads to keep a reasoning model from writing a long thinking block first - a server whose 400/422 names `chat_template_kwargs` is asked again without it and remembered in `_NO_THINKING_REJECTED`; any other 400, such as a prompt over the context size, is an ordinary failure; a `<think>` block the reply opens itself is cut off). A request ends after `timeout_s` in all, retry included, not per wait: `_post` reads the body in pieces and checks the deadline between them, so a server that trickles is dropped (the connection closes and the server stops generating); the caller gives up one second after the deadline whatever happens (`LlmError.timed_out`), so polish and cleanup return and the text stays unchanged. Every request writes one INFO line to the file log as `nexusvox.llm` (`_log_request`): `LLM request: <server> (<protocol>), model <name>, <ms> ms, <outcome>` with the outcome `ok`, `ok, thinking stripped`, `timeout` or `error: <short reason>`; never the text, the API key or a password in the address. Prompts live in `dictation/polish.py`; never write "polish" in them - small models read it as the language (gemma3:4b translated to Polish). `build_user_message` adds a language line detected from the first 2,000 characters of the selection (lingua, ten languages, at least 70 % sure; unsure or mixed → no line), never from the instruction, because a German instruction on English text turned 11-13 of 26 replies German. The line says a translation or language-switch request in the instruction is followed, otherwise the reply stays in the text's language; there is deliberately no keyword gate for translation requests (the model decides; wording tested in docs/llm-cpu-test.md: 0 of 26 wrong-language, 10 of 10 explicit requests). Model choice: `gemma4:e4b` (~+4.6 GB, ~0.5 s warm, keeps tone and language) is the default; `qwen3.5:4b` adds placeholders and switches to formal address, `qwen3.5:9b` leaked a Chinese word, `gemma4:12b` is best but needs ~8 GB more. Feedback sounds go through `app/feedback.py` `_play(beep)` (one place, patched in tests with `patch_app`). Before the model runs, `App._polish_selection` offers the selection and the spoken instruction to the extensions' `on_selection_command` (`ExtensionRegistry.selection_command`, first string wins, saved as `[extension] <command>`). When none handles it, the resolved instruction (preset or spoken words) goes through `ExtensionRegistry.expand_instruction` (`Extension.expand_instruction`, chained in load order, a failing extension skipped) before `polish()`; the saved row keeps the spoken words. The model's answer then goes through `ExtensionRegistry.polish_result` (`Extension.polish_result(result, app, model)`, chained in load order, a failing, empty or non-string answer skipped, its own `selection_deadline()`) before the paste. Both paths paste through `_paste_over_selection`. Likewise `pipeline.process_text(extend_fn=...)` runs the `on_dictation` chain last (`App._extend_dictation`, never for the phone); hooks run on a helper thread with `extensions.HOOK_TIMEOUT_S`, and a failing, timed-out or non-string result is skipped. API version stays 1 (docs/EXTENSIONS.md).

## Auto Cleanup

`dictation/cleanup.py` — opt-in via `[cleanup].level` (`off` default, `light`, `medium`; dashboard select in Text & Polish, read per dictation). Step 5 of `pipeline.process_text`: after voice commands (so it sees digits and the line breaks from "new line"), before translation; the result is typed and translated, the transcript is saved as spoken, and a cleaned dictation is not learnable. The dictation goes to the [llm] model (the fast model when per-task models are on, `llm.config_for(config, "dictation_cleanup")`; polish asks `config_for(config, "polish")`, both the main model by default, see `docs/internals/configuration.md`) inside `<dictation>` tags with `PROMPTS[level]` (`light`: fillers, false starts, accidental repeats, punctuation and capitalisation only; `medium`: also grammar and slightly more concise), the request timeout is `[cleanup].timeout_s` (default 3 s with a CUDA GPU, 10 s without - unset only; not `[llm].timeout_s`), a leading `<think>` block, a code fence and echoed tags are stripped (`llm.clean_reply`, shared with polish), and the dictation's edge whitespace is kept. Typed unchanged: dictations under `MIN_WORDS` (3), `LlmError`, and any reply `plausible()` rejects - a line break lost, a tab or voice-command symbol (`/ \ | ~ * ( ) [ ] { } < > # % + =`) lost or added, a word in capitals ("all caps", acronyms) re-cased or dropped, more than 1.25× the words, or a word-level difflib ratio under 0.6 (`light`) / 0.4 (`medium`). The prompt forbids answering, carrying out, adding and translating, with three examples; before them gemma4:e4b answered "what is the capital of France" with "Paris" and wrote the e-mail a dictation asked for (medium). `llm.warm_up` loads every model in use (`llm.active_models`, so the fast model too) in a background thread at start, when the dashboard switches cleanup on and when the user picks a model (the same one again included), because a cold model (10-50 s) would otherwise time every dictation out. A cleanup that times out also starts `llm.reload_in_background` (protocol `ollama` only; one warm-up request per server and model, at least 180 s and never shorter than `[llm].timeout_s`, sent inside `background()` so live requests go first, never cancelled early): Ollama aborts a half-loaded model when the client disconnects, so after an Ollama restart or unload the short cleanup requests could never load it. While that reload runs (`llm.reload_running`) `cleanup()` skips the model call and types at once; the dictation that timed out is typed unchanged and the next one after the load is cleaned up again. For Ollama `warm_up` is `reload_in_background` itself (long deadline so a slow first load is not aborted, one load per server and model, `reload_running()` true meanwhile, inside `background()`); other protocols keep a plain short request. A Polish request that times out starts the reload through `llm.reload_unless_loaded`, which skips it when `/api/ps` shows the model loaded (then it was only slow, and a reload would switch auto cleanup off for nothing); the selection stays unchanged. Switching the model while a load runs still starts a load for the new model. `scripts/cleanup_eval.py` runs 15 DE/EN dictations (fillers, questions, orders, injection, mixed language, digits, line breaks) against the live server (all pass at both levels with `gemma4:e4b`, ~0.6 s warm).
