# Runtime internals

How the app object, the config, the file log, the data paths and the single-instance guard are put together. Rules: `src/nexusvox/CLAUDE.md`. Module paths such as `app/core.py` are relative to `src/nexusvox/`; paths that start with a top-level folder (`tests/`, `docs/`, `docker/`, `scripts/`) are from the repository root.

## App Layout

`NexusVoxApp` (`App` below) is one class put together from mixins, one module each. `app/core.py` holds `__init__`, the main loop and shutdown; `app/events.py` the hotkey, phone and os-control callbacks; `app/cycle.py` `_transcription_cycle` and the audio stream; `app/commands.py` the extension hooks and commands; `app/polish.py` the paste key and Polish; `app/models.py` model switching and `apply_startup_fallback`; `app/records.py` the saved rows, audio files and statistics; `app/feedback.py` the cues; `app/common.py` the shared logger (every part logs as `nexusvox.app`) and `QUICK_TAP_S`. All state lives on the one instance and is set up in `__init__`. Quit from the tray cancels the main task (`_main_task`), so whatever it waits for ends at once; `_run` calls `_shutdown` in a `finally`, so a crash of the main loop still unmutes other apps and finalizes an open meeting. `_shutdown` releases the mic guard first and runs every step through `_shutdown_step` (a failure is logged, the rest still run); the wait for the statistics pool runs in the executor, off the loop. Background tasks (the warm-up, the phone server) go through `_spawn`, which keeps a reference in `_tasks` until they end, because the loop holds tasks only weakly. A dictation and a model switch exclude each other: `switch_model` refuses while `_cycle_running`, and a cycle that starts while `_switch_in_progress()` takes the offline path (`_offline_stop`: error cue; paste-last and a polish tap still work). Each module imports what it uses, so tests replace those names with `patch_app` (`tests/app_parts.py`), not `monkeypatch.setattr` on `nexusvox.app.core`.

## Config Layout

`config.py` stays the one public import path: `from nexusvox.config import ...` works for every name, and `nexusvox-pro`, the scripts and the tests all import from there (`tests/test_config_exports.py` pins the list). The sections themselves live in `config_sections/`: `hotkey.py`, `meeting.py`, `inference.py` (also `MODEL_REGISTRY`), `storage.py` (`[audio]`, `[database]`), `llm.py` (`[llm]`, `[cleanup]`, `[polish]`), `voice_commands.py`, `integrations.py` (`[assistant]`, `[os_control]`, `[translator]`, `[remote_mic]`, `[support]`) and `features.py` (`[os_commands]`, `[experimental]`, `[mic_guard]`, `[feedback]`, `[learn_from_edits]`). A new section's dataclass goes there and is re-exported from `config.py`. `load_config`, `save_config`, `Config`, the hardware probes (`resolve_device`, `cuda_available`, `gpu_vram_gb`, `auto_llm_model`, ...) and `EXAMPLE_CONFIG_PATH` stay in `config.py` on purpose: a patch of `nexusvox.config.cuda_available` only reaches code in that module, and `__file__` there is what finds the template. The private parsers that log stay there too, so their lines keep the logger name `nexusvox.config`. A section module never imports `config.py`. `save_config` builds the whole file from `_section` / `_toml_value` / `_toml_str` (one writer: a new field is a `(key, value)` pair, never a hand-written f-string), encodes it first and swaps it in with `os.replace` (`_write_atomic`), so a value that cannot be written (`TypeError`) or an interrupted write leaves the old file intact; lone surrogates become U+FFFD, non-string entries of the apps table and the symbol lists are dropped with a warning, and `[database].path` is written as the file had it (`Config.database_path_configured`) while it still resolves to the live path, so the installed app's relative path stays relative. After a save it logs `Settings saved: section.key, ...` at INFO with the names (never the values) of the keys that changed, nothing when none did, and `Settings file created` for a new file. `load_config` moves a file that is not valid TOML to `config.toml.broken-<timestamp>`, logs a warning and starts from the template. `tests/test_config.py` walks every string field of `Config`, so a field the writer misses fails there.

## File Log

`system/logsetup.py` - `setup_file_logging` (called from `__main__` after `basicConfig`) adds a `_DailyFileHandler` (a `TimedRotatingFileHandler`: midnight, UTF-8, opened lazily; a rollover that fails because another process holds the file is skipped until the next midnight, never retried per record) on the root logger writing `%LOCALAPPDATA%\NexusVox\logs\nexusvox.log`; files named `nexusvox.log*` not written for 7 days are deleted at start and after each rollover (`delete_old_logs`, the one retention rule, no `backupCount`); an unwritable folder returns None and the app starts anyway; the startup "Config:" line names the file. The handler's level is `[general].log_level`. Dictated or transcribed text is logged as `Text(...)` (a `str` marker) wherever it appears (transcribers, cleanup, translator, os-control); `ShortenTextFormatter` formats a *copy* of the record so the file shows `'first 20 chars...' (N chars)` while the console keeps the full text; `[general].log_full_text` turns the shortening off and is read per record (live from the dashboard). The file also fences every `Text` between two private-use characters (`TEXT_START` U+E000, `TEXT_END` U+E001; characters of that kind inside the text are dropped), shortened or whole, and writes `LOG_FORMAT_MARK` at each start and rollover: the dashboard's log report (`system/feedback_send.py`, `docs/internals/dashboard.md`) cuts the fenced text out and only reads the file from its first mark on (a restart writes another mark; lines before the first may predate the fences). New log calls that carry spoken text must wrap it in `Text`; `tests/test_logsetup.py` scans every `logger.*` call for common text names (`text`, `reply`, `typed`, ...) passed without it. The DEBUG `transcription.done` line logs the payload without its text, and the text shortened. The dashboard Settings has *Open log folder* (`POST /api/log-folder/open`, `os.startfile`) and *Log Full Text* (`POST /api/settings/log-full-text`, 400 unless `enabled` is a real boolean, `log_full_text` and `log_dir` in `GET /api/settings`).

## Data paths and single instance

`system/paths.py` - where config, data and models live. From source nothing changes (`config.toml`, `nexusvox.db` and `audio/` relative to the working directory, models in the Hugging Face cache). When frozen (`sys.frozen`, the installed app): config in `%APPDATA%\NexusVox`, a relative `[database].path` resolved into `%LOCALAPPDATA%\NexusVox\data`, models in `%LOCALAPPDATA%\NexusVox\models` (`models_dir()`, the one place to change when a custom models folder setting arrives; `apply_models_dir()` sets `HF_HUB_CACHE` for Parakeet and Whisper gets `download_root`; it also sets `HF_XET_CACHE` to the sibling `models-xet` folder, because the xet chunk cache holds model data too and would otherwise sit in the user profile, out of reach of the uninstaller's "delete the models"). `ensure_dirs()` creates the folders on first start. `docker_ctl` and `switch_model` raise `DOCKER_UNAVAILABLE_MSG` when frozen instead of failing on missing compose files. `tests/test_paths.py` covers both modes.

`system/single_instance.py` — one NexusVox per Windows session. `__main__.main` calls `SingleInstance.acquire()` first (named mutex `Local\\NexusVox-single-instance`); a second start rings the named event `Local\\NexusVox-open-dashboard` (`ring_running_instance`) and exits before the tray, hotkey hook or config work exist. The running instance waits on the event in a daemon thread (`watch`) and calls `NexusVoxApp.open_dashboard_from_second_start`. The mutex is also read as taken on ERROR_ACCESS_DENIED (the running instance is elevated); it is created with a DACL (`_MUTEX_SDDL`) that lets any logged-on user open it with SYNCHRONIZE only, because the Inno Setup installer's `AppMutex` check opens it that way to refuse an install or uninstall over a running NexusVox (an elevated instance with default security would read as "not running" to a normal-rights Setup); the event is created before the mutex, and `main` calls `release()` in a `finally`, which closes both handles so a restart during shutdown can take over. If nobody answers the ring, a message box says NexusVox is already running. Tests use per-test object names so a real running NexusVox cannot interfere.

**Start modes.** The installer's autostart Run entry passes `--autostart` (`__main__.is_autostart`), which becomes `NexusVoxApp(autostart=True)`: the app stays in the tray. Any other start (Start menu, desktop shortcut, command line) opens the dashboard once the tray is up in `_serve`; a config whose first-run setup is due opens it either way.
