# NexusVox — Core Runtime

## Hotkey Modes

`hotkey.py` — `HotkeyListener` does all of its work inside pynput's `win32_event_filter`, i.e. synchronously in the WH_KEYBOARD_LL hook on raw virtual-key codes (`_handle(vk, pressed) -> swallow?`), because that is the only place an event can still be suppressed (`Listener.suppress_event()`). The binding is `[hotkey].modifiers` plus an optional `[hotkey].key` (names → VK codes in `config.HOTKEY_KEY_VKS`; validated by `validate_hotkey`, an unusable binding in the file falls back to the default). Both the binding and `config.mode` are re-read from the shared config on every event, so the dashboard is live (`_sync_binding` resets the pressed-state tracking, keeps `_active`). Left and right modifier variants both count. Edge detection via `_combo_down`: a *complete press* is the last missing modifier going down (modifier-only binding) or the key going down while all modifiers are down (the key must come last, so "hold A, then Ctrl" never records); releasing any key of the combo resets it. Hold: complete press activates, first key up deactivates. Toggle: each complete press flips `_active`; releases do nothing. Swallowing rule: modifiers are always passed through; the key-down that completes the combo is swallowed and `_key_swallowed` then swallows every event of that key (auto-repeats, the final key-up) until it is physically released — so in hold mode the letter is dead for the whole recording (even after the modifiers went up), and in toggle mode it types again the moment the user lets go; a key pressed without all modifiers is plain typing. Do not filter injected events (PowerToys/AutoHotkey remaps arrive injected). `active` is the recording intent in both modes and is what `app.py` consults before the cycle's `finally` release of the mic guard. `still_recording()` is the mic-guard watchdog check: physical key state (`GetAsyncKeyState`, modifiers and key) in hold mode, `_active` in toggle mode, because in toggle mode the keys are up while recording. Mode switch mid-recording: hold→toggle keeps recording until the next press; toggle→hold stops on the next key release. **Menu mask:** a binding with Alt or Win would open the focused app's menu (Notepad, Word) or Start when that key is released with nothing typed since it went down, which releasing Ctrl/Shift first leaves behind. `HotkeyListener._mask_menu_keys` therefore types a neutral key (VK `0xE8`, `injector.send_menu_mask`, AutoHotkey's mask key) when the combo completes, and again when a second Alt/Win goes down during it - never at the release: sent from inside the hook it would queue behind the key-up it must precede. The sender is wired in `start()` (import outside the hook), so unit tests never inject. A lone Alt tap is left alone. `injector._release_all_modifiers` puts the mask before its synthetic Alt key-up when Alt or Win is still down (one atomic SendInput batch). `describe_hotkey()` renders the binding for logs.

**Marker keys** (`_marker_keys`, re-read on every event): pressed during a recording with every binding modifier down, a marker key is swallowed (with its repeats and key-up) and turns that recording into something else. `[os_control].command_key` (when enabled) makes it a command recording (`command`, fires `on_command` for `::show`); `[hotkey].paste_key` (default `V`, empty = off) makes it `paste_last`: `app.py` drops the recording without transcribing and pastes `App._last_typed` (the text the last dictation pasted, in memory only - the saved transcript is the spoken text, which differs once translated; nothing yet → error beep). The first marker pressed wins; the command key wins a clash of keys, and the binding's own key is never a marker. Without all modifiers down, or outside a recording, the key types normally. The mark (`HotkeyListener.mark`: `COMMAND`, `PASTE_LAST`, `POLISH` or None) is read once right after the stop, also on the "released before recording could start" skip path, so a quick tap still pastes; a dictation that typed nothing (only "press enter") leaves `_last_typed` alone. Known gap: the cycle connects to the transcription server before recording, so the paste key does nothing while the server is unreachable. `[hotkey].polish_key` (default off) is the third marker, `polish`: see Polish.

## Polish

`polish.py` + `llm.py` — the polish marker key makes the recording an instruction for the selected text. After the transcript arrives, `App._polish_selection` reads the selection with `polish.read_selection`: first `uia.read_focus` asks the focused control through UI Automation (TextPattern `GetSelection`; no key sent, clipboard untouched; an empty reported selection counts as nothing selected). A terminal (Windows Terminal, console host, mintty, ConEmu, PuTTY by window class; xterm.js and `TermControl` by focused element) gets **no** Ctrl+C by default - with nothing selected it would interrupt the running program - and polish beeps; `[polish].in_terminals` (dashboard toggle, read per polish) lets a terminal get Ctrl+C like any other control, and the reply is then pasted at the prompt (a terminal's selection is in its output, not editable). Only a control that does not report its selection falls back to `injector.copy_selection` (clipboard emptied, Ctrl+C via the shared `_send_ctrl_chord`, polled up to 1 s, original clipboard put back; `injector` is imported inside `read_selection` because it binds Win32 at import). A quick tap of the polish chord (released before recording started) polishes with the default instruction and saves nothing. A polish key equal to the paste key in `config.toml` is dropped on load. The spoken instruction goes through `polish_presets.resolve_instruction` first: a preset name at its start (`polish_presets` table, edited in the dashboard; matched with `snippets.best_option`, so case, spaces, hyphens and close spellings do not matter) is replaced by the preset's instruction, with the words after the name appended as `Also: ...`; nothing said uses the preset marked default (at most one, enforced in `Database.save_polish_preset`). The row is saved as `[polish] <preset name>` then. Presets are user-defined only, so the bilingual rule is met by the user, as with snippets. It then sends selection + instruction (or `DEFAULT_INSTRUCTION` when nothing was said and there is no default preset) to the model and pastes the reply over the still-selected text (`inject_text`, so Ctrl+Z in the app undoes it); saved as `[polish] <instruction>`, and `_last_typed` becomes the reply. The reply keeps the selection's leading/trailing whitespace (a selected line keeps its newline) and loses a leading `<think>` block (protocol `openai` cannot turn thinking off). If the foreground window changed while the model worked, nothing is pasted (error beep); the paste key still pastes the reply. Nothing selected, `LlmError` (server down, timeout, empty or malformed reply) or `ClipboardError` → error beep, selection untouched. A password field (`CurrentIsPassword`) counts as nothing selected, and so does a selection that reaches the 100,000-character `GetText` cap - the reply would be pasted over text the model never saw. `llm.complete` speaks Ollama's `/api/chat` (`think: false` for reasoning models, `keep_alive`) or OpenAI-compatible `/chat/completions` (`protocol = "openai"`, optional Bearer `api_key`). Prompts live in `polish.py`; never write "polish" in them - small models read it as the language (gemma3:4b translated to Polish). Model choice measured 2026-10-18 on the RTX 5070 Ti with Parakeet loaded (~7.3 GB baseline, user's cap ~12 GB): `gemma4:e4b` +4.6 GB, ~0.5 s warm, keeps tone and language (default); `qwen3.5:4b` +3.8 GB adds placeholders and switches to formal address; `qwen3.5:9b` leaked a Chinese word; `gemma4:12b` best but +8 GB. Feedback sounds go through `app._play(beep)` (one place, patched in tests). Before the model runs, `App._polish_selection` offers the selection and the spoken instruction to the extensions' `on_selection_command` (`ExtensionRegistry.selection_command`, first string wins, saved as `[extension] <command>`); both paths paste through `_paste_over_selection`. Likewise `pipeline.process_text(extend_fn=...)` runs the `on_dictation` chain last (`App._extend_dictation`, never for the phone); hooks run on a helper thread with `extensions.HOOK_TIMEOUT_S`, and a failing, timed-out or non-string result is skipped. API version stays 1 (docs/EXTENSIONS.md).

## Auto Cleanup

`cleanup.py` — opt-in via `[cleanup].level` (`off` default, `light`, `medium`; dashboard select in Voice Input, read per dictation). Step 5 of `pipeline.process_text`: after voice commands (so it sees snippet placeholders, digits and the line breaks from "new line"), before translation; the result is typed and translated, the transcript is saved as spoken, and a cleaned dictation is not learnable. The dictation goes to the [llm] model inside `<dictation>` tags with `PROMPTS[level]` (`light`: fillers, false starts, accidental repeats, punctuation and capitalisation only; `medium`: also grammar and slightly more concise), the request timeout is `[cleanup].timeout_s` (default 3 s, not `[llm].timeout_s`), a leading `<think>` block, a code fence and echoed tags are stripped (`llm.clean_reply`, shared with polish), a sentence mark the model put after a snippet placeholder at the very end is dropped again (`mark_snippets` drops it on purpose), and the dictation's edge whitespace is kept. Typed unchanged: dictations under `MIN_WORDS` (3), `LlmError`, and any reply `plausible()` rejects - a line break or private-use placeholder lost, a tab or voice-command symbol (`/ \ | ~ * ( ) [ ] { } < > # % + =`) lost or added, a word in capitals ("all caps", acronyms) re-cased or dropped, more than 1.25× the words, or a word-level difflib ratio under 0.6 (`light`) / 0.4 (`medium`). The prompt forbids answering, carrying out, adding and translating, with three examples; before them gemma4:e4b answered "what is the capital of France" with "Paris" and wrote the e-mail a dictation asked for (medium). `llm.warm_up` loads the model in a background thread at start and when the dashboard switches cleanup on, because a cold model (10-50 s) would otherwise time every dictation out. `scripts/cleanup_eval.py` runs 16 DE/EN dictations (fillers, questions, orders, injection, mixed language, digits, line breaks, a placeholder) against the live server; 2026-10-18 with gemma4:e4b: all pass at both levels, ~0.6 s warm.

## Transcriber Architecture

`BaseTranscriber` ABC (`needs_docker: bool = True` class attr) with a factory pattern. Four implementations:

- **`VoxtralRealtimeTranscriber`** — streams audio chunks over WebSocket to vLLM's `/v1/realtime` endpoint
- **`OpenAIHttpTranscriber`** — buffers audio in memory, POSTs a WAV file to an OpenAI-compatible `/v1/audio/transcriptions` HTTP endpoint (used by Cohere Transcribe, Parakeet TDT, and GPU-backed Whisper). Dictation sends only `file` and `model`. `supports_word_timestamps` (class attr on `BaseTranscriber`, True here) says the client can; `transcribe_file(word_timestamps=True)` sets `word_timestamps = True` when the model's registry entry also has `word_timestamps` (Parakeet only), which adds `response_format=verbose_json` and `timestamp_granularities[]=word`; `docker/parakeet_server.py` then also returns `words` (`{word, start, end}` in seconds) and `TranscriptionResult.words` holds them. Engines without timing leave it empty. `supports_diarization` (True here) plus the registry's `diarization` flag (Parakeet only) let `transcribe_file(diarize=True)` call `diarize(wav, timeout)`: the whole file (bytes or a file object) is POSTed once to `/v1/audio/diarization` next to the transcription URL (`diarization_url`), and the reply `{segments: [{speaker, start, end}]}` becomes `SpeakerTurn`s (`parse_turns`)
- **`LocalWhisperTranscriber`** (`transcribers/local_whisper.py`) — in-process faster-whisper, no Docker. Class-level `_model_cache` keeps loaded models warm across switches. `needs_docker = False`. Blocking `WhisperModel.transcribe()` runs in `loop.run_in_executor` to keep the asyncio loop responsive.
- **`LocalParakeetTranscriber`** (`transcribers/local_parakeet.py`) — Parakeet TDT 0.6B v3 on CPU through `onnx-asr` (`nemo-parakeet-tdt-0.6b-v3`, `quantization="int8"`, ONNX Runtime CPU provider, ~670 MB from `istupakov/parakeet-tdt-0.6b-v3-onnx` on first use). Same shape as the Whisper one: class-level `_model_cache`, background load on `connect()` (`_begin_preload`: one at a time, set to `loading`/`downloading` before the thread starts, none after a failed load - the next `finish()` makes the one retry, and a new transcriber clears the error), `needs_docker = False`. Recognition runs on the class's own single-thread executor, so jobs queue there and not in the default pool; `finish()` sets a `cancelled` event on timeout, which makes a queued or running job stop (between VAD segments) instead of working on a result nobody reads, and resets the buffer even when a load or ONNX error propagates. The registry entry carries `inprocess_engine: "parakeet-onnx"` (plus `onnx_model`, `onnx_quantization`) next to `inprocess_supported: True` and `requires_gpu: False`, which is how `create_transcriber` tells it from Whisper; on GPU the same entry is still the Docker NeMo container. Audio up to `MAX_DIRECT_S` (20 s) goes to the model in one call; longer audio (a 60 s upload chunk) is cut by onnx-asr's Silero VAD (`with_vad(max_speech_duration_s=20)`, loaded on first need) and the segments' text is joined. Word timing (`word_timestamps`, set by `transcribe_file`) comes from the token timestamps: `words_from_tokens` opens a word at every token that starts with the SentencePiece mark (onnx-asr already turns `▁` into a space, both are accepted), so punctuation stays on its word, also when its token carries the mark (onnx-asr drops the space before a non-word character in the text, the words follow it); a word runs from its first token to one frame (`FRAME_S`, 80 ms) after its last, capped at the next word; segment words are shifted by the segment start. `supports_diarization` stays False: speaker detection lives in the Parakeet container, the engine carries `no_diarization_reason` ("Speaker detection needs the GPU container"), and both `get_current_model` (`diarization: false` + `diarization_hint`, read from the running transcriber through the `get_transcriber` callback, never from the device setting) and an upload that asks for speakers (a note) take it from there. `load_status()` (`idle`/`downloading`/`loading`/`ready`/`error`, lock-free because `_get_model` holds `_cache_lock` for the whole download) reaches the dashboard through `NexusVoxApp.get_switch_status` whenever no switch is in flight (idle or just ready: `downloading`, `loading`, or `error` with the reason); `_preload_transcriber` runs at start and after a switch to any in-process model. Measured 2026-10-20 on the dev machine's CPU: 46 s one-off download, a 34 s upload decodes in 4 s.

`create_transcriber(config, *, device, language, auto_detect_language)` dispatches:
- `custom-server` (registry flag `custom`) → `_create_custom_transcriber`: `[inference.custom].protocol` `http`/`realtime` picks `OpenAIHttpTranscriber`/`VoxtralRealtimeTranscriber` on `[inference.custom].url`, with `model = model_name` and `needs_docker = False` set on the instance. Empty url raises. `[inference].server_url` is not touched. `model_needs_docker()` in `config.py` is the single Docker decision for `switch_model`; a failed switch restores the old model and URL in the config. The wire contract users implement is `docs/CUSTOM_SERVER.md`; keep it in sync with both transcriber classes.
- CPU + `inprocess_supported=True` → `LocalParakeetTranscriber` when the entry has `inprocess_engine: "parakeet-onnx"`, else `LocalWhisperTranscriber`
- CPU + `requires_gpu=True` (Voxtral, Cohere) → raises with a clear "switch models" error
- Otherwise → protocol-based dispatch (`realtime_ws` or `openai_http`)

Device resolution: `resolve_device("auto")` probes `ctranslate2.get_cuda_device_count()`. CTranslate2 ships with faster-whisper, so no extra detection dep. Active model set in `config.toml` under `[inference].model`; device under `[inference].device` (`auto`/`cuda`/`cpu`). Both switchable at runtime via the dashboard.

## Speaker Diarization (file uploads)

`diarization.py` — pure merge logic. `transcribe_file(..., diarize=True)` (implies word timestamps) starts speaker detection as a task (`_diarize_file`) **before** the 60 s chunks are transcribed, since it does not need the transcript: the whole file goes to the server **once**, so speaker indices stay the same across chunks. The WAV is written straight from `wav_chunks` into one `BytesIO` (`_whole_file_wav`, no second PCM copy) and handed to httpx as a file object. `_DIARIZE_LOCK` (process-wide, polled so a cancelled task never holds it) lets one speaker request at a time leave this app, and the timeout `diarization_timeout(duration_s)` (300 s base for loading or first downloading the model, plus 0.5 s per second of audio) starts only after the lock is taken, so a second upload never spends its timeout waiting behind the first; chunk calls keep their 120 s. A failed transcription cancels the task. `label_words` gives each word the speaker whose turn holds its midpoint (overlapping turns: the one covering more of the word; a word in no turn: the nearest turn) and numbers speakers 1, 2, ... in order of first appearance; `format_transcript` joins consecutive words of one speaker into `Speaker N: ...` paragraphs separated by a blank line, which become the saved and returned text, and each stored word carries `speaker`. The labelled text is built from the words, so labelling is skipped (plain transcript plus a note) when any chunk returned fewer timed words than its text has words (the server drops a word whose timing it cannot read); a timed-out chunk does not block it, its text is missing from the plain transcript too. A model without the `diarization` flag (the note names the flagged models via `speaker_detection_models()`), a client without `supports_diarization`, a failed request (timeout, server down) and an empty turn list also return the plain transcript with a note, never an error. `diarization_url` maps `.../transcriptions` to `.../diarization` and any other URL to `/v1/audio/diarization` on the same host.

Server side (`docker/parakeet_server.py`): `nvidia/diar_streaming_sortformer_4spk-v2` (CC-BY-4.0, at most 4 speakers) is loaded on the first diarization request only, into CPU memory and outside the GPU lock (the first download does not stall dictation), with the model card's "very high latency" streaming preset. `_gpu_lock` puts one model on the GPU at a time: transcriptions now run in the thread pool (`run_in_threadpool`, so waiting never blocks the event loop and `/health`) and take the lock; a diarization run takes it, moves Sortformer to the GPU, and afterwards back to the CPU plus `torch.cuda.empty_cache()`, so VRAM returns to the Parakeet-only level. A dictation that arrives during a run waits for it (a 10-minute file takes ~2.4 s). Loading Sortformer also turns off Parakeet's CUDA-graph decoder (`_disable_cuda_graph_decoding`): with graphs captured before a Sortformer run, the next transcription dies with "CUDA error: an illegal memory access" and takes the container down (reproduced with plain request order transcribe → diarize → transcribe, independent of the CPU offload and the lock). Graphs off costs ~35 ms per 5 s dictation and ~130 ms per 30 s, so they stay on until the first diarization request. It needs NeMo ≥ 2.5 (`spkcache_update_period`); `docker/Dockerfile.parakeet` pins 2.7.3 and uninstalls the base image's `nvidia-modelopt`, which fails to import with the newer transformers NeMo brings. Verified 2026-10-19 on the RTX 5070 Ti: first request ~3 s with the model cached (load included), then ~0.5 s for 30 s of audio; a 10-minute two-voice file labelled consistently across all 10 chunks, upload 9.5 s with speakers vs 7.3 s without.

## Upload Cleanup (file uploads)

`file_cleanup.py` — optional LLM cleanup of an uploaded file's transcript (dashboard *Clean up text*, level `light`/`medium`), reusing `cleanup.cleanup()` with its prompts and `plausible()` check; no prompt of its own. The pieces are slices of the transcript itself, with the whitespace between them kept, and a transcript in which no piece changed comes back byte for byte (so a dead model never stores a whitespace-only "cleaned" version). `split_paragraphs` cuts the transcript at blank lines (the `Speaker N: ` label of a diarized block is split off, never sent to the model and put back) and `split_pieces` cuts each block at sentence ends into pieces of at most `MAX_WORDS` (120) words (a sentence longer than that is cut after a comma, semicolon or colon in its second half where there is one, else by words; a full stop after "Dr.", "z. B.", "bzw." and similar does not end a sentence), so a cut rarely lands mid-clause and invites a false sentence break from the "fix punctuation" prompt, because a small model loses the thread on a long monologue and a transcript without speakers is one long block. Each piece is one `cleanup()` call with `CleanupConfig(timeout_s=[llm].timeout_s)`, not the 3 s dictation timeout. A piece the model fails on, answers implausibly or leaves alone keeps its own words, so the cleaned transcript is always complete. After `MAX_CONSECUTIVE_FAILURES` (3) `LlmError`s in a row the remaining pieces are skipped (a server that is down would otherwise cost the full timeout per piece); only a piece the model actually answered resets the streak (a piece too short to send does not), and an implausible reply counts as an answer. Pieces under `MIN_PIECE_WORDS` (2) words are not sent (dictation skips under 3: `cleanup(min_words=)`), so a turn like "um hi." is cleaned and a single word is left alone. The requests run inside `llm.background()`: `llm.complete` counts live requests (dictation cleanup, polish) and a background request waits, up to `BACKGROUND_WAIT_S` (30 s), until none runs, so a live request waits behind at most the one piece already in flight, not behind the whole upload. `TranscriptCleanup.note` says how many passages stayed as spoken and becomes a job note. The result is stored beside the raw transcript; the transcript and its word timings stay untouched. English and German go through the same prompts; both are covered in `tests/test_file_cleanup.py`.

## Extensions

`extensions.py` - optional packages register an `Extension` under the `nexusvox.extensions` entry-point group (class, instance or zero-argument factory); `ExtensionRegistry.load()` runs once at start through `load_extensions()` (started on a background thread from `NexusVoxApp.__init__`, so a heavy package never delays the hotkey, and called by `open_dashboard`, which waits for it; process-wide, idempotent, reentrant). Nothing installed means nothing changes. Everything an extension does is wrapped: an import error, a missing or taken `name`, another `api_version` (must equal `API_VERSION`, bumped only on a breaking change), a missing `api_version` (no default on purpose: a default of `API_VERSION` would be inherited after a bump), a raising `dashboard_panels()` / `export_targets()`, a malformed / duplicate panel or target id, a relative or missing `static_dir` or an export suffix / media type that is not header-safe skips the extension or the item with a log line; a raising hook becomes a job note. Seven hooks (`display_text(transcript, text)` is the seventh, see below): `on_file_transcribed(FileTranscript)` runs in `DashboardAPI.upload_and_transcribe` after the save, on the job's worker thread (results land under `extensions[<name>]` in the job result, a `note` key becomes a note; the result must be a JSON-serialisable dict), `dashboard_panels()` (`DashboardPanel`: static dir served at `/ext/<id>/`, optional Flask blueprint mounted at `/api/ext/<id>/`, script registers with `NexusVoxExt.registerPanel`) and `export_targets()` (`ExportTarget`: download link per stored upload, `GET /api/file-transcriptions/<id>/export/<target>`; optional `available(id)` fills `exports_unavailable` per upload in the list and greys the link) and `upload_actions()` (`UploadAction`: a button per upload card that POSTs to an `endpoint` or calls a handler a `panel` script registers with `NexusVoxExt.registerUploadAction`). `on_dictation(text, ActiveApp)` and `on_selection_command(selection, command, ActiveApp)` (both added without an `API_VERSION` bump; `ActiveApp` = process file name + window title from `window_manager.foreground_app`) are text hooks: `ExtensionRegistry._text_hook` runs each on a daemon helper thread under one `HOOK_TIMEOUT_S` deadline for the whole chain (entry-point order; `dictation` chains the results, `selection_command` takes the first string, wired in `pipeline.process_text(extend_fn=)` and `App._polish_selection`); an exception (`SystemExit` included), a non-string result or a timeout skips that extension, and a hook still busy from a timeout is not called again. The app reaches them through `loaded_extensions()`, which returns None until the startup load is done (it never waits, so a heavy package cannot delay a dictation) and does not read the active app when nothing is installed. `display_text(FileTranscript, text)` (additive, `API_VERSION` stays 1) changes the transcript texts shown in the Upload/Meetings lists (`DashboardAPI._displayed`, only when an extension is loaded) and written by the built-in TXT/SRT/VTT exports (`builtin_export_targets(registry.display_texts)`, cue texts after `build_cues`); `ExtensionRegistry.display_texts` runs each extension over all texts in one helper thread (`_guarded`, which also holds the `_stuck` bookkeeping under a lock; `HOOK_TIMEOUT_S` + `DISPLAY_TEXT_S` per text, or a `deadline=` the dashboard shares across a whole list), a text it fails on keeps its wording, a timeout leaves all texts raw; cue texts are re-wrapped by `exports._displayed_cue` and an answer with `-->` is dropped. The `available` checks of exports and actions run through the same `_guarded` under the list's deadline. `UploadAction.available(id)` (same answers as `ExportTarget.available`) fills `actions_unavailable` per upload in the list and greys the button. `exports.py` holds the built-in export targets `txt`, `srt`, `vtt` (`builtin_export_targets`, registered first by `load_extensions` so extension ids cannot take them). `FileTranscript` is the frozen hook view of a `file_transcriptions` row (`file_transcript_from_record`). `DashboardAPI(extensions=)` defaults to an empty registry, so tests never see installed packages; they register a dummy `Extension` on their own `ExtensionRegistry`. Contract for extension authors: `docs/EXTENSIONS.md` - keep it in sync with the module.

## vLLM Realtime Protocol

The WebSocket protocol requires a specific commit sequence:

1. Receive `session.created` from server
2. Send `session.update` with model name
3. **Send non-final `input_audio_buffer.commit`** — this starts the generation engine
4. Send `input_audio_buffer.append` chunks (base64 PCM16)
5. Send `input_audio_buffer.commit` with `final: true` — signals end of audio

Without step 3, the server never starts processing audio. This was a hard-won bug fix.

**Logprobs are not available** in the realtime WebSocket protocol. The `transcription.done` message only returns token counts in the `usage` dict (`prompt_tokens`, `completion_tokens`, `total_tokens`). The `transcription.delta` messages only contain `type` and `delta` (text). Confidence extraction code exists in `TranscriptionResult` and will activate automatically if vLLM adds logprob support.

## SendInput INPUT Struct

The ctypes `INPUT` struct union **must** include `MOUSEINPUT` (not just `KEYBDINPUT`) so that `ctypes.sizeof(INPUT)` returns 40 bytes on 64-bit Windows. With only `KEYBDINPUT` the struct is 32 bytes, and `SendInput` silently returns 0 — no error code, no exception. The modifier-release step (`_release_all_modifiers`) and configurable `injection_delay_ms` are also required because the push-to-talk hotkey (Ctrl+Shift+Alt) can leave stale modifier state. `inject_text` first polls `GetAsyncKeyState` until the user has physically released all modifiers, because the hotkey deactivates on the *first* modifier going up. **Never wrap the Ctrl+V `SendInput` in `AttachThreadInput`**: SendInput does not need it, and detaching right after the call re-syncs the target thread's key state while it may still be processing the V keydown — the app then reads Ctrl as up and types a literal "v" (intermittent). `_paste_via_message` uses `GetGUIThreadInfo` to find the focused control for the same reason. **Clipboard writes go through `clipboard.set_text`, never `pyperclip.copy`**: it adds the formats `CanIncludeInClipboardHistory` / `CanUploadToCloudClipboard` (DWORD 0) and `ExcludeClipboardContentFromMonitorProcessing`, so the pasted text and the restored clipboard stay out of the Win+V history (with pyperclip every dictation left two entries there and a polish several; verified 2026-10-18 through `Windows.ApplicationModel.DataTransfer.Clipboard.GetHistoryItemsAsync`). Reads still use `pyperclip.paste`. The one entry NexusVox cannot keep out is the app's own Ctrl+C in polish's clipboard fallback. `set_text` retries `OpenClipboard` for ~500 ms (`_OPEN_ATTEMPTS`, as long as pyperclip waited) and raises `ClipboardError`; `inject_text` puts the user's clipboard back ~300 ms after Ctrl+V (`_RESTORE_DELAY_S`), because Electron apps and terminals read the clipboard late and pasted the old content when it came back after 100 ms. It returns the `time.monotonic()` at which the text was in place (before that wait), and `latency_ms` ends there, so the restore delay never counts as latency. Every caller of `inject_text` catches `ClipboardError`: a dictation then plays the error beep, is still saved and kept as `_last_typed` (the paste key pastes it).

## Correction Dictionary

`dictionary.py` — `apply_dictionary(text, entries)` runs on the raw transcription after the nexus/assistant checks and before voice commands. Entries (`wrong` → `right`) live in the `dictionary_entries` table, edited in the dashboard Settings tab. Matching is whole-word, case-insensitive, whitespace-tolerant; longest `wrong` phrase wins; `right` is inserted verbatim. `suggest_entries(original, corrected)` diffs a review correction token-wise (case-sensitive, so "cloud code" → "Claude Code" stays one phrase) and returns only `replace` blocks — insertions/deletions are usually fillers, not misheard terms.

## Snippets

`snippets.py` — user-defined only (`snippets` table, edited in the dashboard Settings > Snippets card; none ship). A trigger matches anywhere in the dictation, whole-word, case- and whitespace-insensitive, longest trigger first; a sentence mark right after a trigger at the end of the dictation is dropped. Triggers are free text in the user's own language, so the bilingual rule is met by the user, not by a built-in vocabulary. In the text pipeline (`pipeline.py`), `mark_snippets` runs on the dictionary-corrected text (after the "press enter" split) and swaps each match for a private-use placeholder (`U+E000 + n`); voice commands and the translator see only the placeholder, so an expansion such as "tab" or a German address is inserted verbatim. After translation, `placeholders_intact` checks the translator kept every placeholder exactly once (else the untranslated text is injected, `translate_error = "snippet placeholder lost"`), then `expand_snippets` restores the stored text for injection and for the saved transcript. Learn from edits ignores a correction inside a snippet's text: the placeholder, not the expansion, is in the `spoken` text a learned entry must match.

**Options:** a snippet may carry `options` (`SnippetOption(name, text)`; stored as JSON `[name, text]` pairs in the `options` column and decoded only in `Database._snippet`; the API takes and returns `[{name, text}]`, and the dashboard's `name = text` text box is parsed in `dashboard.js`; `GET /api/snippets/github-repos` returns `gh repo list` as options). The words after the trigger (comma/colon allowed in between) pick the option: `best_option` scores the first 1-5 words against every name after squashing both to lower-case letters and digits ("Nexus Box" vs "NexusVox"), keeps the best `difflib` ratio ≥ 0.75 and prefers the longer span on a tie ("nexus vox site" → `nexusvox-site`, not `NexusVox`). No option close enough → the plain `expansion`, or the trigger stays text when that is empty.

**nexus open:** the grammar lives in `os_commands.py`: `parse_nexus_open` returns what follows `nexus` + a verb (`open`, `öffne`, `öffnen`, `öffnet`), and `strip_open_verb` drops such a verb. `snippets.resolve_open_target` compares that rest against every trigger without its own leading verb, so the trigger "open remote repo" answers both "nexus open remote repo …" and "nexus öffne remote repo …"; the rest must be exactly one snippet match. It is the first command `App._run_command` tries and does not need `[os_commands].enabled` (the user's snippet is the opt-in). The text is opened with `window_manager.open_target`: only `http(s)://`/`mailto:` URLs or existing paths, via `os.startfile` (ShellExecute → the running default browser opens a new tab in its last-used window). Anything else plays the error beep and nothing is typed; saved as `[nexus] open <target>`. Without `nexus`, the same phrase types the URL. `window_manager` stays a lazy import in `app.py` (tests replace it through `sys.modules`).

## Learn From Edits

`edit_watch.py` — opt-in via `[learn_from_edits].enabled` (checked per paste in `app.py`, so the dashboard toggle is live). After `inject_text`, `EditWatcher.watch(text, window_s)` hands the pasted text to one worker thread (own COM init via `mic_guard._ensure_com`; no COM pointer crosses threads, the hotkey hook never blocks). The worker takes the UI Automation focused element (`UiaTextField.focused()`; it raises `FieldSkipped` for `CurrentIsPassword` and for a terminal - `uia.foreground_is_terminal` / `uia.is_terminal_element`, the same lists polish uses), reads it via ValuePattern or TextPattern until the pasted text shows up (apps paste asynchronously, up to 2 s; not found → skip). The paste is found with any run of whitespace matching any other (`_find_last`), so a field that re-wraps or re-indents it still counts, then re-reads every second for `window_s` (default 20 s), keeping the last readable text. A new `watch()` (the next dictation) ends the running one early; its result still counts. `extract_edit(before, injected, after)` finds the paste in `before` (last occurrence, whitespace-tolerant), maps the span onto `after` through a character diff (common prefix/suffix trimmed first) — text typed right before or after the span stays outside it — and rejects deleted or rewritten spans (char similarity < 0.5). `learn()` then requires half the dictated words kept and at most 2 changed places, runs `dictionary.suggest_entries` and drops replacements over 4 words and language mix-ups (`_language_switch`: both sides two words or more, lingua's top guesses differ and one side is ≥ 0.9 sure — Parakeet sometimes hears German "jetzt aber" as "it's our", and such an entry would rewrite real English; short phrases rarely get a confident guess on both sides, so one sure side is enough). Results go to `Database.add_dictionary_suggestions` (`dictionary_suggestions` table, duplicates and existing entries skipped) — never straight into the dictionary; the dashboard accepts or dismisses them. Skipped for remote-mic pastes and for dictations auto cleanup or translation changed (`ProcessedText.learnable`). Voice commands, snippets and "press enter" no longer drop the whole dictation: `ProcessedText.spoken` (the text after the dictionary, snippets as placeholders) goes along, and `learn()` keeps only entries that `apply_dictionary` would apply to it, so a fix of "25" typed for "fünfundzwanzig" or of a snippet's text is dropped while a misheard name next to a "new line" is learned. Every paste ends in one outcome (`OUTCOMES`: suggested; the watched ones that taught nothing - `unchanged`, `too_small` (only line breaks moved; a different run of spaces, a non-breaking space for instance, counts as `unchanged`), `rewritten` (dictation deleted or char similarity under 0.5), `too_many_changes`, `no_replacement`, `lost_field` (the element died before any edit was seen); the skipped ones - processed, clipboard, terminal, password, no_field, unreadable, too_long, not_found), logged at INFO with the numbers behind it (`Verdict.detail`) and how the watch ended (time window over / next dictation arrived / field unreadable), and counted in `EditWatcher.status()` (`watched` is `WATCHED_KEYS`, derived from `OUTCOMES`: every outcome whose message does not start with "skipped"; the dashboard uses it to tell watched from skipped, and it is answered without the app too). `judge()` returns the `Verdict`, `learn()` is its suggestions only. A failed read (`UiaTextField.read` keeps `last_error` and logs at DEBUG; the watcher announces a dead field at INFO once per watch, so a field rebuilt on every poll does not flood the log) makes the watcher fetch the focused element again through the one helper `_refetch(accept, stop)` (`_REFETCH_TRIES` tries of 0.2 s; also when the very first read dies, even after it saw the old text without the paste: `_read_pasted` returns `died` besides the reason, and the reason it had seen - too_long, not_found - is what gets recorded if no other element helps). For the first read `accept` is a single read that must show the paste (no 2 s wait per try). In the watch loop `stop` is the deadline or a waiting dictation, so a refetch never outlasts the window or delays the next watch. A password field or terminal met while refetching ends the first read as `password`/`terminal`; in the loop it ends the watch as unreadable. In the loop a re-fetched element is adopted only when `_still_ours` says it is the same field: not much longer than the first read (twice its length + 500 characters, else it is a page), and the paste itself is in it, or - for fields up to 2,000 characters - the whole text is still 60% similar to the first read and `extract_edit` finds the fixed dictation. The dictated words alone never decide, since a results page holds them too. Focus that moved to another field or page is never diffed, and the last successful read is what gets judged when nothing usable comes back. A dead field with a `unchanged` or `too_small` verdict is `lost_field`, since no edit was seen. Known gap, address bar of Chrome/Edge: inline autocomplete glues a completion to the last dictated word and a search rewrite replaces the words, so the words-kept filter (not the char similarity) reports `too_many_changes`; nothing is learned there on purpose. `[general].log_level` (`DEBUG`/`INFO`/`WARNING`/`ERROR`, default `INFO`, read once in `__main__`) sets the level of the `nexusvox` loggers; the root stays at INFO or above, so DEBUG does not flood the console with comtypes and urllib3; `app.py` records the outcomes it decides itself through `skip()`. The dashboard shows the last outcome and the counts since start under the toggle. Accepting a suggestion drops the other pending ones for the same `wrong`. Fields over 20,000 characters are not watched. Terminals are skipped on purpose: xterm.js (Orca, VS Code, Electron terminals) focuses an always-empty `xterm-helper-textarea`, and Windows Terminal's buffer is hard-wrapped and often over the size limit, so the paste was never found there (verified 2026-10-18).

## Voice Commands

`voice_commands.py` converts spoken phrases into characters/transforms before text injection. Runs after nexus check, only if `[voice_commands].enabled = true` in config.

- **Structural** (own category, opt-out via `structural` list, `bypass_structural` skips them all; default all on): `new line`, `new paragraph`, `tab`, `all caps`. Keywords in `structural` are the canonical English ones; their aliases (`newline`, `tabulator`, `neue Zeile`, `neuer Absatz`, `Tabulator`, `alles groß`, ...) fire whenever the canonical keyword is enabled
- **Symbols** (opt-in via `symbols` list, German aliases such as `Schrägstrich`, `Klammer auf` fire with the English keyword): `slash`, `backslash`, `pipe`, `tilde`, `asterisk`, `open/close paren/bracket/brace`, `less/greater than` (safe defaults) + `hash`, `percent`, `dash`, `hyphen`, `plus`, `equal`, `colon`, `star` (ambiguous, disabled by default)
- **Numbers** (opt-in via `numbers_as_digits = true`): spoken number words → digits in English and German in one pass (German first), including compounds ("twenty five" → "25", "one thousand five hundred" → "1500", "fünfundzwanzig" → "25", "zweihundertdreiundvierzig" → "243", "zwei tausend fünf hundert" → "2500"). German `ein`/`eine`/... are articles and only count directly before `hundert`/`tausend`/`Million(en)`/`Milliarde(n)`; `Million(en)`/`Milliarde(n)` need a multiplier in front

- **Press enter** (opt-in via `press_enter = true`, needs `enabled`): `split_press_enter()` strips a *trailing* `press enter` / `hit enter` / `Enter drücken` / `drück(e) Enter` (comma before it dropped, sentence punctuation kept) right after the dictionary, before the other voice commands and translation; `inject_text(..., press_enter=True)` sends Enter (VK_RETURN + scan code) 100 ms after the paste, or Enter alone when nothing is left (saved as `[press enter]`). Not applied to remote-mic recordings — the phone inserts the text itself

**Bilingual rule:** every spoken vocabulary (commands, numbers, anything new that matches speech) covers English and German from the start. There is no language switch in the matcher; both are always recognised, and every new feature ships with German tests.

Symbol commands do not break `all caps` mode; structural commands do. Pattern is compiled per (active symbols, active structural) pair and cached via `lru_cache`. `ALL_SYMBOL_INFO` and `ALL_STRUCTURAL_INFO` (public) are consumed by the dashboard UI to render per-keyword toggle chips (with the German aliases as tooltip data).

## Nexus OS Command Layer

`os_commands.py` + `window_manager.py` — checked before voice commands. If transcription matches a nexus pattern, executes the command and skips text injection entirely.

- Window management: `"nexus <action> <app>"` — open, close, focus, fullscreen, minimize, snap left/right
- Requires `os_commands.enabled = true` and app registered under `[os_commands.apps]` in `config.toml`
- Force-foreground uses AttachThreadInput + Alt key trick + SPI timeout fallback (Vista+ restriction workaround)
- **"nexus flag"** is always available regardless of `os_commands.enabled` — flags most recent transcription for review, no DB record for the flag itself

## Assistant Forward

`assistant.py` — checked after the nexus flag/OS commands, before voice commands, only when `[assistant].enabled`. `"nexus assistant <text>"` (also `assistent`, an optional comma/colon) sends `send <service> <text>` to `host:port` over TCP, one request per connection, client shuts its write side, reply is one line. Saved to the DB as `[assistant] <text>`, nothing injected. `OSError` (nothing listening) plays `beep_error` and falls through to normal injection, so a sentence is never lost. The TCP contract, shared with `[os_control]` command recordings, is documented for users in `docs/CONTROL_PORT.md`; keep it in sync when the protocol changes.

## Translate Before Inject

`translator.py` — `translate(text, config)` runs on the processed text (after dictionary and voice commands) right before injection, only when `[translator].enabled`. It POSTs `{"text": ...}` to `[translator].url` - the personal-tooling `translator` server, TranslateGemma via Ollama on 127.0.0.1:8003, which translates German sentences and passes English ones through byte for byte - and injects the reply. The transcript is saved as spoken, never translated. Any failure (nothing listening, non-200, malformed reply, timeout) logs a warning and returns the original text, so a sentence is never lost. The tray item "Translate to English (local server): ON/OFF" flips `enabled` and saves the config. `is_reachable(config)` POSTs an empty text with a 1.5 s cap; any HTTP answer counts, and the dashboard shows the result under the toggle (`/api/settings/translator-status`) so the toggle never looks self-contained. The contract is documented for users in `docs/TRANSLATOR.md`. Blocking HTTP, run in the executor like the injection. `translate()` returns a `TranslateResult` (text, translated, source, ms, error); the last four are saved on the transcription row (`translated`, `translate_source`, `translate_ms`, `translate_error`) so the dashboard overview can report how often translation ran, its average server time, and how often the fallback fired.

## Mic Guard

`mic_guard.py` — opt-in via `[mic_guard].enabled` (dashboard Settings > Voice Input toggle; the guard is always constructed and `app.py` checks the flag on every hold, so the toggle is live). On key-down every WASAPI audio session on the default *capture* endpoint (pycaw's `AudioUtilities` helpers only look at the render endpoint, so `enumerate_capture_sessions` asks `IMMDeviceEnumerator` for `eCapture` explicitly) that is not PID 0 and not our own PID is muted through `ISimpleAudioVolume`, but only if it was unmuted; on key-up those sessions are set back to unmuted. Never the endpoint device. NexusVox is a single process, so `os.getpid()` is the whole exclusion. `MicGuard` is pure logic over a `CaptureSession` protocol (tests use fakes); `WasapiCaptureSession` is the real thing. Sessions are re-enumerated on every hold and release and matched by `GetSessionInstanceIdentifier`, so no COM pointer ever crosses threads and COM is initialised per thread (`_ensure_com`, MTA, `RPC_E_CHANGED_MODE` tolerated). `SetMute` costs ~40 ms per session and pynput runs the hotkey callbacks inside the low-level keyboard hook, so `app.py` calls `hold_async()` / `release_async()`: one worker thread, FIFO, so a very short tap still muted-then-restores in order; the record-start event is set at the same time, dictation start is not delayed. Nothing may stay muted: `release()` is idempotent and runs on key-up, in the `finally` of `_transcription_cycle`, in `_shutdown`, via `atexit`, and from a watchdog (`watchdog_s`, default 30 s) that only fires when `HotkeyListener.modifiers_physically_down()` (GetAsyncKeyState, independent of the hook) says the keys are up — a long dictation re-arms it. During a hold the muted sessions are in `mic_guard_state.json` next to the database; `restore_leftovers()` runs at startup and matches on the stable `GetSessionIdentifier` too, because Windows persists per-app mute across app restarts. Known gaps: an app that starts capturing mid-hold is not muted until the next hold, and **Discord ignores session mute entirely** (verified 2026-09-13: mute flag set, Discord's voice activity ring still lights; an ordinary WASAPI/MME capture stream and a Chrome getUserMedia stream both go to exactly 0.0 within 300 ms, so browser calls are covered). The supported answer for Discord is its own *Push to Mute* keybind on the NexusVox hotkey; say so in any user-facing text about this feature.

## Meeting Recorder

`meeting_recorder.py` - records the default microphone and the system output (WASAPI loopback) at the same time into one folder per meeting (`<base>/meeting-YYYYMMDD-HHMMSS/`: `mic.wav`, `system.wav`, `meeting.json`). Independent of dictation: own streams, nothing in `audio.py` changed, so dictation keeps working during a meeting (`app.py` only reports each take's time range). Started from the dashboard and the meeting hotkey through `MeetingSession` (see Meeting Session); `python -m nexusvox.meeting_recorder [--dir audio/meetings] [--seconds N]` runs it by hand. Each track keeps its device's native rate and channel count (mic via sounddevice `RawInputStream` int16; system via **PyAudioWPatch**, chosen because it ships WASAPI loopback in one wheel for Windows and sounddevice's PortAudio has none; `soundcard` was the alternative). `AudioSource` (`describe()`, `start(sink)`, `stop()`) is the seam tests fake. The audio callback only stamps the block with the clock and `put_nowait`s it onto a bounded queue (full queue: block dropped and counted in `meeting.json`); one writer thread per track streams it to a `wave` file, so memory stays flat. All tracks share one `t0`. `TrackWriter.write` knows when a block arrived and keeps the track within `GAP_TOLERANCE_S` (0.25 s) of the shared clock: the first block pads the whole offset from `t0`, a larger deficit later (loopback sends nothing during silence) is filled with zeros, a larger surplus (fast device clock) is dropped from the block, and `finish()` pads to the stop time, so both files end up as long as the meeting within that tolerance. Blocks dropped on a full queue are counted in frames and padded back before the next block. `describe()` resolves and pins the device (the loopback source keeps one PyAudio instance from `describe()` to `stop()`), all sources are described before `t0` is taken, and `start()` opens exactly that device and format. `meeting.json` (`started_at` UTC, `dictations`: `[{start_s, end_s}]` seconds from `t0` of every dictation take, `MeetingRecorder.begin_dictation` / `end_dictation` (under a lock shared with `stop()`, so a late take never rewrites the finished file), rewritten into the file at once; `App` reports each non-remote take through an executor (`_begin_take` after the recording started, from the hotkey press (`_press_time`) so a slow server connection does not cut off the first words; `_end_take` at the stop and again in the cycle's `finally`, so a failed take is stored too) via `DashboardAPI.begin_dictation` / `end_dictation` -> `MeetingSession`, whatever `[meeting].leave_dictation_out` says; a take still open when the meeting stops lasts until the stop, and one that began before the meeting is cut at its start; `ended_at`, per track file/rate/channels/frames/duration, `dropped_blocks`, `error`) is written at start (`ended_at` null) and again at stop; `stop()` closes every track even when one fails and records the failure in `meeting.json`; a failed `start()` removes the folder and raises the original error. A process killed mid-meeting leaves WAV headers with a wrong length; `meeting_transcribe.load_meeting` repairs them (see Meeting Transcript). Tests: `tests/test_meeting_recorder.py` (fake sources and clock, including 60 simulated minutes with flat memory).

## Meeting Transcript

`meeting_transcribe.py` + `DashboardAPI.transcribe_meeting` / `start_meeting_transcription(folder)` (runs on the same `FileJobs` as uploads; `DashboardAPI.stop_meeting` starts it when a recording ends; the save, extension hook and result dict are shared with uploads in `_store_file_transcription`). `load_meeting` reads `meeting.json` and repairs each WAV header from the actual file size (`repair_wav_header`: only opened for writing when the header is wrong, RIFF and data sizes rewritten, a partial last frame cut). `ended_at: null` marks the folder interrupted (a note), its tracks are still transcribed - but the recorder also writes null while recording, so a file written to within `STALE_AFTER_S` (30 s) is never repaired and loading such a folder raises ("may still be recording"). Each track is read window by window (60 s of its own device rate), downmixed and resampled to 16 kHz mono (`convert_track` also writes it to a temporary 16 kHz WAV for the mix), so clock differences between the devices cannot shift one track against the other; memory holds one window plus the WAV chunks of the track being transcribed (`transcribe_file` takes a list), about 115 MB per hour, one track at a time. The chunks go through `transcribe_file(word_timestamps=True)` like an upload (no 25 MB limit on this path); the row's confidence is the mean of the tracks'. `merge_words` drops echo from Me (`drop_echo`: a Me word has an echo partner when an Others word within `ECHO_SLACK_S` is at least `ECHO_SIMILARITY` similar (casefolded, so umlauts and ß work), and only runs of `ECHO_MIN_RUN` (3) consecutive partnered Me words are dropped, so a lone "yes"/"okay" or "the"/"they" in crosstalk stays; bisect search, not quadratic), then (with `[meeting].leave_dictation_out`, default on, read at transcription time so a re-transcribed folder follows the current setting) drops the Me words that overlap a dictation range of `meeting.json` padded by `DICTATION_MARGIN_S` (0.5 s; `drop_dictation`, before the echo filter; without word timing nothing can be dropped and a note says so; the audio files are never touched), then labels the words `speaker` 1 = Me (`mic.wav`), 2 = Others (`system.wav`) and orders them by time; `format_transcript(words, names)` writes `Me: ...` / `Others: ...` paragraphs, the saved text. When a track has fewer timed words than words in its text (an engine without timing, or the server skipping words), nothing is interleaved: each track's full text follows the other (a note), like the upload path's `words_complete` check. `mix_tracks` writes `meeting.wav` (16 kHz mono, via a `.tmp` file moved into place, so a failed mix leaves no partial file) next to the tracks, which stay untouched: each track's speech RMS (50 ms blocks within 20 dB of its loud blocks, above a noise floor) is brought to `TARGET_RMS`, with gain limited to `MIN_GAIN`..`MAX_GAIN` so a near-silent track is not boosted into noise, and the sum is scaled by `PEAK_LIMIT` / (sum of the gained track peaks) so it cannot clip; one analysis pass per track, one mixing pass. The row is saved with `kind = "meeting"` and `audio_path` (relative to the database folder, `DashboardAPI._db_dir`); `GET /api/file-transcriptions/<id>/audio` serves it, the Upload history shows an audio player for rows that have one, and `FileTranscript.kind` carries the marker to `on_file_transcribed` (additive, `API_VERSION` stays 1).

## Meeting Session

`meeting_session.py` - `MeetingSession(config.meeting, base_dir, recorder_factory)`: thread-safe `start()` / `stop()` / `status()` (`{recording, elapsed_s, folder}`) around `MeetingRecorder`, built per meeting from the current `[meeting]` devices (`MicSource(name)`, `LoopbackSource(name)`: the named device, matched on WASAPI names; a missing device logs a warning and falls back to the default; `list_devices()` feeds the dashboard selects). One session lives in `DashboardAPI` (`start_meeting`, `stop_meeting` = recorder stop + `start_meeting_transcription`, `toggle_meeting`, `shutdown_meeting` on quit so the WAV headers are closed); meetings go to `<database folder>/<[database].audio_dir>/meetings/`. A `busy` stop (another file transcribing) leaves the audio in its folder without a row. The meeting hotkey is `hotkey.MeetingHotkey`, a second pynput listener of its own (toggle, modifiers + required key, binding re-read per event, so the dashboard is live). It fires only when exactly its modifiers are held (a superset such as Ctrl+Shift+Alt+M is dictation's paste-last) and the modifiers it counts are intersected with `GetAsyncKeyState` on every press, so a key-up the hook never saw (Ctrl+Alt+Del) cannot leave one "held"; the key is swallowed only when it fires. `meeting_hotkey_clash` / `validate_meeting_hotkey` refuse a missing key, no modifier and any chord the dictation listener also fires on (it fires on every chord that holds its modifiers and key: equal, or a superset when the dictation hotkey is modifier-only or ends in the same key); `DashboardAPI.set_hotkey` runs the same check the other way round, and `load_config` falls back through `default_meeting_hotkey` when a hand-edited file clashes. The hook only hands off to a thread (`App._toggle_meeting`, non-blocking lock: a press while the previous one is still being handled is ignored): `ensure_dashboard_api` starts the Flask server without opening the browser, `toggle_meeting(ask_consent=True)` (under `DashboardAPI._meeting_lock`, which the dashboard buttons share) answers `action` `start` / `stop` / `consent`; `consent` (hint on) opens the dashboard on `#meetings`, because the hint is shown there; a stop that only found the transcriber `busy` still plays the stop beep (the recording ended). A recording without a transcript (busy stop, quit mid-meeting, failed job) is listed by `get_pending_meetings` (folders with `meeting.json` and no `kind="meeting"` row, except the one recording or transcribing) and can be transcribed or deleted from the Meetings tab. Dictation is untouched during a meeting (separate streams and listener). `DashboardAPI.delete_file_transcription` deletes an upload (its stored audio when inside the database folder) or a meeting (the folder, found next to the mix or by name in the meetings directory, only when named `meeting-*` and holding `meeting.json`); missing files never block it. `_remove_folder` deletes `meeting.json` last, so a locked file (a player, a scanner) fails the delete with the row and the marker still there and a retry finishes it. Device lists: `_refresh_devices` re-initialises PortAudio so a headset plugged in later shows up and a saved device is found, but only while no stream is open (`audio_state.streams_open()`, counted by dictation and the meeting microphone; a module of its own so reading it needs no PortAudio). A named output is matched to its loopback by the exact name `<output> [Loopback]` first, the substring only as fallback. Docs for users: `docs/MEETINGS.md`. Tests: `tests/test_meeting_dashboard.py`.

## Audio Persistence

Each recording saved as 16kHz mono WAV in the configurable `audio/` directory alongside the database, unless `[database].store_audio` is false (`App._store_audio` checks the flag per recording, so the dashboard toggle is live; the transcript row is saved either way with `audio_path` NULL, which the Review queue already filters out). Enables batch review with playback in the dashboard Review/Edit tabs.
