# Hotkey internals

How `dictation/hotkey.py` decides, swallows and cancels. Rules: `src/nexusvox/CLAUDE.md`. For users: `docs/hotkey-modes.md`. Module paths such as `app/core.py` are relative to `src/nexusvox/`; paths that start with a top-level folder (`tests/`, `docs/`, `docker/`, `scripts/`) are from the repository root.

## Hotkey Modes

`dictation/hotkey.py` — `HotkeyListener` does all of its work inside pynput's `win32_event_filter`, i.e. synchronously in the WH_KEYBOARD_LL hook on raw virtual-key codes (`_handle(vk, pressed) -> swallow?`), because that is the only place an event can still be suppressed (`Listener.suppress_event()`). The binding is `[hotkey].modifiers` plus an optional `[hotkey].key` (names → VK codes in `config.HOTKEY_KEY_VKS`; validated by `validate_hotkey`, an unusable binding in the file falls back to the default). Both the binding and `config.mode` are re-read from the shared config on every event, so the dashboard is live (`_sync_binding` resets the pressed-state tracking, keeps `_active`). Left and right modifier variants both count. Edge detection via `_combo_down`: a *complete press* is the last missing modifier going down (modifier-only binding) or the key going down while all modifiers are down (the key must come last, so "hold A, then Ctrl" never records); releasing any key of the combo resets it. Hold: complete press activates, first key up deactivates. Toggle: each complete press flips `_active`; releases do nothing. Swallowing rule: modifiers are always passed through; the key-down that completes the combo is swallowed and `_key_swallowed` then swallows every event of that key (auto-repeats, the final key-up) until it is physically released — so in hold mode the letter is dead for the whole recording (even after the modifiers went up), and in toggle mode it types again the moment the user lets go; a key pressed without all modifiers is plain typing. Do not filter injected events (PowerToys/AutoHotkey remaps arrive injected). `active` is the recording intent in both modes and is what `app/cycle.py` consults before the cycle's `finally` release of the mic guard. `still_recording()` is the mic-guard watchdog check: physical key state (`GetAsyncKeyState`, modifiers and key) in hold mode, `_active` in toggle mode, because in toggle mode the keys are up while recording. Mode switch mid-recording: hold→toggle keeps recording until the next press; toggle→hold stops on the next key release. **Menu mask:** a binding with Alt or Win would open the focused app's menu (Notepad, Word) or Start when that key is released with nothing typed since it went down, which releasing Ctrl/Shift first leaves behind. `HotkeyListener._mask_menu_keys` therefore types a neutral key (VK `0xE8`, `injector.send_menu_mask`, AutoHotkey's mask key) when the combo completes, and again when a second Alt/Win goes down during it - never at the release: sent from inside the hook it would queue behind the key-up it must precede. The sender is wired in `start()` (import outside the hook), so unit tests never inject. An auto-repeat of a held modifier is not a press and gets no mask. `MeetingHotkey` sends the same mask when its chord fires, because it swallows the chord key too (`_mask_sender`, wired in its `start()`); without it Ctrl+Alt+M opened the app's menu and Win+Shift+M the Start menu on every meeting toggle. **Lost key-ups:** before a binding key press decides, `HotkeyListener._heal_modifiers` drops tracked modifiers that are not physically down (`GetAsyncKeyState`, like `MeetingHotkey`), so a key-up the hook never saw (Ctrl+Alt+Del, the lock screen) cannot leave Ctrl+Alt "held" and turn a later plain letter into a recording that swallows it. A lone Alt tap is left alone. `injector._release_all_modifiers` sends key-ups only for modifiers that are still down (`_held_modifiers`; none after `wait_for_physical_release`, the normal case): a key-up for an Alt that is already up is a lone Alt release that toggles Notepad's menu bar (and one for Win opens Start). With Alt or Win still down, the mask goes in before the first such key-up (one atomic SendInput batch). `__main__` logs the module path and `branch@commit` at start (`Code:` line). `describe_hotkey()` renders the binding for logs.

**Toggle markers, Escape, cap:** in toggle mode a marker key also ends the recording (`_finish`) unless it is pressed in the hold that started it (`_start_hold`: it then only marks). A modifier-only binding delays the stop chord by `STOP_GRACE_S` (0.3 s, a `threading.Timer`, `grace_s`/`timer_factory` injectable) so "hotkey + marker" works; a binding with a key stops at once. Escape while `active` calls `on_cancel` and is swallowed (key-up and repeats too); otherwise it passes through. `App` stores the latest stop in `_stop_info` as `(mark, cancelled, stop gesture time)` from the stop callback and the cycle reads it once per take (one slot, not a queue: start/stop events collapse, a queue would drift out of step; no race with the next take's reset mark). Escape counts only without other modifiers physically down (`_other_modifiers_down`); the cap skips phone recordings; a polish tap (< `QUICK_TAP_S`) whose `finish()` fails (HTTP backends fail there, not in `connect()`) still polishes with the default instruction. `[hotkey].max_recording_s` (default 600, 0 = off) ends a recording in the cycle with `asyncio.wait_for`, clears the toggle intent and releases the mic guard. A connect failure goes to `App._offline_stop`: paste-last and a default polish still run. The tap test uses the press time the cycle read at its start, because `_press_time` moves on with the next press. A stop still set when the connection is up, with the hotkey held again, comes from an earlier tap: it is dropped and the held press records, since skipping would leave its release as a stale stop for every later take. Toggle takes under `MIN_TOGGLE_TAKE_S` are dropped. Details for users: `docs/hotkey-modes.md`.

**Foreign keys:** a key-down that is neither a binding modifier, the binding's key, a marker key nor Escape calls `_discard_on_foreign_key` -> `_cancel_recording` (same `on_cancel` path as Escape; the cancelled flag in `_stop_info` means 'dropped', not necessarily Escape) while the start chord is still held: Hold within `FOREIGN_KEY_WINDOW_S` (1 s) of the start, Toggle while `_start_hold` (cleared when a binding modifier is released, so later typing never touches the recording). Never swallowed. Not counted: injected events (`LLKHF_INJECTED`, passed from `_win32_event_filter` as `_handle(..., injected=)`) and non-typing keys (`_is_typing_key`: mouse, browser/volume/media, VK_PACKET, menu mask 0xE8, 0xF6+). The check is lock-free, it runs for every key typed. A chord that completes while a modifier outside the binding is physically down (`_extra_modifiers_down`) does not start (and a key binding's key is not swallowed); a stop is never refused. Covers Ctrl+Win+Left/Right (virtual desktops) and Ctrl+Win+Alt+letter. In `App._transcription_cycle` the start tray/chime/overlay for hold and toggle (not phone) are scheduled with `loop.call_later` `START_CUE_DELAY_S` (0.15 s from the key press) after `audio.start()`; `show_start_cue` skips when stopped, a release inside the delay that is not a discard shows it at once (start/stop pair), a discard never shows it. The mic guard still mutes at the press and is released by the discard.

**Marker keys** (`_marker_keys`, re-read on every event): pressed during a recording with every binding modifier down, a marker key is swallowed (with its repeats and key-up) and turns that recording into something else. `[os_control].command_key` (when enabled) makes it a command recording (`command`, fires `on_command` for `::show`); `[hotkey].paste_key` (default `V`, empty = off) makes it `paste_last`: `app/cycle.py` drops the recording without transcribing and pastes `App._last_typed` (the text the last dictation pasted, in memory only - the saved transcript is the spoken text, which differs once translated; nothing yet → error beep). The first marker pressed wins; the command key wins a clash of keys, and the binding's own key is never a marker. Without all modifiers down, or outside a recording, the key types normally. The mark (`HotkeyListener.mark`: `COMMAND`, `PASTE_LAST`, `POLISH` or None) is read once right after the stop, also on the "released before recording could start" skip path, so a quick tap still pastes; a dictation that typed nothing (only "press enter") leaves `_last_typed` alone. Known gap: the cycle connects to the transcription server before recording, so the paste key does nothing while the server is unreachable. `[hotkey].polish_key` (default off) is the third marker, `polish`: see Polish.
